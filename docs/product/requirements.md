# 产品要求

状态：当前产品要求。本文规定应保持的能力与边界；实现入口和本轮验证范围见[实现核对表](../development/implementation-audit.md)。未来研究与未完成验证见[待办索引](../plans/README.md)，不混入已实现能力。

## 目标与研究自由

依据[设计哲学](philosophy.md)，项目同时服务于执行效果和进化过程的可理解性。用户选择 Meta、固定 Solver、公开开发任务、研究目标和运行上限。Meta 自主决定研究问题、插件划分、框架、依赖、工具、会话、恢复策略及实验顺序。

候选是完整执行工程。平台不能把某个默认工具名、固定 SDK 组合、每轮修改数量、先覆盖全部基线或提交研究记录设为策略准入条件。研究记录与简短修改说明帮助追溯，不能要求先证明科学假设才允许实验。当前 Studio 仍保留次数上限覆盖任务数的旧校验，这是[已确认的实现差距](../plans/README.md#当前已确认的实现差距)，不将它重新定义为产品要求。

主线只承载项目能力、标准 Docker/Harbor、本地证据存储和通用配置契约。具体实例适配与运维属于独立部署分支。部署专属改动不整体合回主线；通用改进先进入主线。

## 四类核心能力

1. **开发与冻结。** Meta 具有文件、搜索、编辑、终端、长任务、资料查询、上下文压缩和普通研究委派能力。工作文件和会话持久保存。生成代码在隔离环境检查，正式候选有明确内容身份，测试与导出使用同一内容。
2. **组合与实验。** Meta 自主安排已检查候选、任务和重复次数，允许无收益、失败和回退。受理、启动和结果保存幂等；没有自动免费重跑整个实验。所有开始过的尝试均保留。
3. **完整证据。** 允许范围内的任务原文、冻结源码、评分报告、轨迹、终端输出和历史报告均有可核验来源。长输出用文件和分页读取，不能把摘要当作全部原件；索引尚未完成或证据缺失时明确说明。
4. **报告与交付。** 系统提供事实与比较限制，Meta 提供解释、假设、反例和选择理由。批次报告与总报告保留修订，选定候选可导出为不依赖 Meta、活动数据库和原仓库的项目。

## 角色与隔离

Solver 只获得本次任务的公开材料和工具，不获得 Meta 研究历史、其他活动、真实供应商凭据、控制数据库或私有评分输入。辅助模型请求也绑定该 Solver。

Meta 通过受控后台修改本活动，不拥有提高用户上限、改写原件、替换官方评分或永久删除活动的权限。普通研究子会话共享研究工作区，业务接口按登记角色授权；这不是针对同域恶意终端代码的强隔离。历史停止审查使用独立隔离环境，适用范围见[兼容规则](../architecture/compatibility.md)。

## 实验控制与计分

- 新活动不提供 token 账本、累计费用、token 总量或参考 token 子额度。用户仍可设置有限墙钟、并发、轮次和实验次数；次数上限可为空，空值不代表零。
- Meta 在用户上限内规划并发和收尾时间。求解、环境准备和评分时限来自 benchmark，各阶段上限独立记录；剩余活动时间不足以覆盖完整上限时仍允许提交和启动，由 Meta 判断是否值得尝试。任务原始时限不改写，活动硬截止仍有效；仅用户显式选择的有限延期模式允许已启动任务延后结束。记录启动及开始求解时可用时间、实际阶段耗时和真实中断原因，比较时显示时间条件差异。实施状态见[晚启动计划](../plans/late-start.md)。
- 暂停阻止新启动并中断当前 Meta，已启动实验继续，墙钟继续。用户停止终止实验并允许剩余时间内收尾；关闭页面或 UI 宿主不停止独立后台。
- Meta 根据用户目标自主决定主动收尾，必须提交结束理由与本次活动的实验总结。平台核验调用权限、有效文本和持久化，不以稳定性规则、评分、实验次数、候选选择、证据列表或报告齐全作为收尾门槛；不审批理由是否充分。活动结束不表示平台认证目标达成。运行机制见[控制后台](../architecture/control.md#暂停停止与探索完成)。
- 主动收尾受理后关闭新增实验，在原有时间与取消约定内处理在途工作和结果归集，完成后结束活动，不要求额外 Meta 回复。用户停止、资源截止和技术故障有独立结束路径；未取得 Meta 总结时明确标记缺失，不将系统摘要冒充 Meta 总结。收尾插件不属于通用入口的前置条件。
- 官方结果与执行异常分开。非零退出或归档失败不抹掉已有可信官方分数；无可信官方评分保持 null。
- 当前任务完成规则将已启动并最终结束的无官方通过尝试计失败，保留原因；未启动、无先行失败的明确人工撤销和未结束记录单列。完整判定顺序见[证据与存储](../architecture/evidence-storage.md)。

## 可读性与证据约束

默认阅读入口应先说明研究问题、当前方向、关键变化和选择，再按需展开插件机制、源码、逐次结果与原件。保留插件、执行版本、实验轮次之间的关联，区分版本父子关系与实验先后顺序。

插件说明包含用途、机制和源码位置；缺失说明如实标注，不能从名称推断效果。同名同版本号但内容不同的插件须区分。研究记录支持动机、观察、转折、无结论、失败和放弃；补充说明标明作者、记录时间和事实时间。

版本选择由 Meta 显式提出，保留当时全部相关尝试、证据摘要、备选、局限和重新考虑条件。最新版本不自动获选，未选不代表已被否定，证据不足不伪造提升。成功率保留分母、任务覆盖与不确定性；配置、环境或资源不同须说明比较限制。

报告区分观察、解释和推测，说明插件是否触发、实际改变了什么、是否有对照和反证。重复测试与消融可以增强证据，项目不预设固定搜索或分析流水线。源码、夹具与少量实验不证明跨任务泛化或长期无人干预研究质量。

跨活动材料须由用户显式纳入并选择访问范围，默认仅用户阅读；原有成绩不并入新活动主线统计。引用准确报告修订和证据，不指向可变的最新正文。

## 参考实验

参考模型与参考 Harness 是两个可独立启用、移除的 Meta 插件，默认关闭。用户选择允许集合及自主/指定配对模式，Meta 只能提交已批准且兼容的组合。原生参考模型配置与主线供应商目录分工明确。

参考模型、参考 Harness、联合参考独立保存结果与轨迹，不抬高主线成绩或稳定完成率。共享活动时间、次数和并发约束，可有次数子限额；新活动没有 token 总账。不能静默换模型或近似转换不兼容协议。

## 持久性、存储与删除

冻结资产与原始证据不可变，安装缓存可重建。后台重启先核实已有进程和工作身份，结果归集重试不重跑模型。存储不足时等待或停止生产者，保留部分输出和根因；容量保护不等于工作区硬配额。

用户可以永久删除一次活动及其所属历史，包括在途活动的停止和清理。删除由独立持久任务协调，失败可重试，完整清理才算成功；共享对象按剩余引用保留，其他活动显式依赖其来源时阻止删除。外部下载和备份不随活动删除。

## 独立交付与工作台

导出包含准确源码、构建产物、配置、锁和必要接入，排除 Meta、研究历史、控制数据库、凭据与安装缓存。包内说明应足以显式配置外部任务环境和认证。静态校验、无模型搬迁、真实独立执行分别记录，不能互相替代。

工作台通过独立桥连接后台，公共客户端承载查询和命令；具体 UI 不互相依赖。切换、刷新和卸载保留幂等身份，不能重复创建活动或自动重发未知结果的写操作。默认 Studio 覆盖完整操作路径。
