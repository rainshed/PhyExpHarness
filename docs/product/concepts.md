# 核心概念

适用范围：当前产品概念；具体旧格式见[兼容规则](../architecture/compatibility.md)。

| 名称 | 含义 |
|---|---|
| Solver | 在单次任务中执行的固定模型；同一主线活动的候选共用其绑定设置 |
| Meta | 研究执行 Harness 的模型，拥有开发、实验、证据读取和报告能力 |
| 执行 Harness | 调用 Solver、管理工具与上下文并提交任务产物的完整工程 |
| 插件 | 具有可说明职责的能力单元；新工程内的插件划分由 Meta 决定 |
| Candidate / 候选 | 一份不可变的工程、依赖锁、配置、构建产物和必要适配身份 |
| Campaign / 活动 | 用户目标、任务范围、固定模型、限额及研究记录的持久容器 |
| Batch / 批次 | 对单个候选、任务集合和重复次数的一次受理；计一轮 |
| Trial / 尝试 | 某个候选对某个任务的一次执行；失败不会从历史消失 |
| H0 | 默认最小基线工程；准备完成不表示已经完成官方任务实验 |
| 官方评分 | 由 benchmark verifier 产生并经归属与完整性核验的分数；缺失保持 null |
| 任务完成分 | 按活动绑定规则派生的成功/失败指标，与官方原始分数分别保存 |
| 参考实验 | 改变模型、Harness 或两者的独立对照；不进入主线候选成绩 |
| 冻结与导出 | 冻结确定不可变内容；导出从该内容装配独立交付包 |

执行版本、Meta 组合、工具协议、系统模板、计分规则和任务环境是不同的版本维度，不能只用一个“v3”指代全部。当前默认值及来源见[架构总览](../architecture/overview.md)。

研究中的设计意图、观察事实和因果解释分别记录。候选被保留表示 Meta 做出了选择；通过构建、拥有官方评分或被选中，都不自动构成稳定性认证。阅读方式见[证据与报告](../guides/evidence-and-reports.md)。
