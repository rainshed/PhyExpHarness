# 自进化活动存储管理

2026-10-25：真实长活动发现逐条证据入库的全表扫描和同步归集阻塞控制循环，新增[控制面与证据规模修复计划](../plans/control-plane-scalability.md)。其中执行结束、结果核验、索引归档分离及持久恢复约束取代下文将结果收集与全部归档串行完成的实现方式；完整原件、权限与不可变引用原则继续适用。

日期：2026-10-23 · 状态：已实现并完成初步工程测试，长任务验收待完成

## 范围与原则

本增量面向重新开始的新活动，不实施历史数据迁移或删除。发布软件不等于清空活动；清空由用户另行执行。固定 Solver、评分、失败记录、用量账本和研究可追溯性保持原有含义。

目标是减少重复写入，在活动运行期间整理已完成内容，并在磁盘耗尽前阻止新的生产者。有限磁盘不能无限保存不断增加的原始证据；容量不足时必须明确等待空间，不能静默丢弃输出后报告成功。

## 正文共享与完整归档

独立的内容存储按 SHA-256 保存不可变正文。完整归档清单保留原始文件路径、摘要、大小；证据索引另存活动范围、用途、来源与稳定 ID，两者引用同一内容对象。证据访问范围不因共享物理存储扩大。

运行目录继续承接写入。仅在生产者退出、结果和用量收集完成后归档；发布对象和校验成功后将原路径转换为共享文件视图。普通文件视图通过同文件系统硬链接复用正文，所有写入者只能写活动文件或原子替换路径，不得原地修改已发布对象。原目录中的清单和共享视图不是第二份正文，保持现有官方校验和诊断入口可用。跨文件系统不能伪称已释放空间。

发布采用临时文件、校验和原子替换；重复执行幂等，异常时保留可验证的源文件。回收必须保留归档、证据、报告、会话和视图的引用，只删除无引用且超过宽限期的受管对象。旧活动不自动转为新格式。

## 分层查询快照

新活动状态文件为小型根清单，引用活动配置、实验、候选、证据、报告、请求等独立内容。列表按稳定身份分片，具体记录按内容共享；新增或改变记录只新增该记录、所属分片和上层清单。过滤条件、视图版本及权限范围参与快照身份。

一次读取在显式 SQLite 读取事务中取得一致状态；事务内读取并发布所引用的不可变对象，最后发布根清单；事务期间不写数据库。重复查询不产生相同正文的副本。倒计时和观察时间留在回执，不使不可变对象变化。旧快照引用始终指向当时内容；不要求模型重放无限增长的增量链。文件路径、格式、分片路径和计数使原生脚本可直接遍历全部数据。

最新指针不代表唯一保留根。已经返回给持久会话的快照、报告和停止审查引用仍可读，压缩与回收不能破坏这些引用。

## 分段日志与读取

RPC、模型审计和受管输出按大小分段。活动段可写；关闭段以 gzip 无损压缩，按顺序和摘要登记。重启恢复处理发布与切换窗口，损坏或丢失段必须报告。正文摘要与压缩文件摘要分开，已捕获输出不会因限额被静默覆盖。

RPC、模型审计和 stderr 不再按单份逻辑日志的累计未压缩字节设 256 MiB 上限，持续增长受活动与全局存储预算、实际磁盘水位约束。约 8 MiB 的分段目标和单次写入最多 256 MiB 保证处理单元有界，大记录独占一段。写入保留至少 64 MiB 紧急余量。工具/终端输出捕获器的显式额度保持独立，不随审计日志累计上限移除而取消。

宿主计量、诊断、回放使用统一日志读取器逐段遍历关闭段及读取开始时的尾段快照；分页查询不会把整份历史日志解压拼接进内存。证据目录公开完整段清单与各段文件，支持分页解压读取，原生分析脚本也可读取 gzip。原生会话恢复文件不按普通日志轮转或删除。

存储故障先记录结构化代码、阶段、时间与安全的观测字段，再取消在途请求。物理空间不足、显式输出额度、单条记录过大和写入错误分别说明；清理阶段的模型取消不得覆盖先行故障，已有更早的终止故障也不被后续写入错误替换。真正磁盘压力后的恢复仍先经过后台总存储准入；确定的记录/输出限额与文件写入问题需处理原因后再恢复。

这些行为随新冻结运行时生效，旧活动的运行时、原始日志和失败文件不自动改写。旧分段格式继续读取，无需转换历史证据。

## 容量与自动回收

控制后台维护全局容量策略、按活动用量、实际文件系统剩余容量及文件数量；硬链接正文只计一次。容量统计和深度扫描节流，不能每次状态查询遍历全部磁盘。

策略包含数据容量上限、活动容量上限、最低剩余字节、每个在途实验的收尾预留、恢复水位、巡检间隔及垃圾宽限期。日志分段与输出限额采用独立的宿主常量。容器存储以实际所在文件系统监测，不使用累计镜像虚拟大小作回收承诺。策略由用户身份配置，Meta 不能提升上限。

启动实验和 Meta 前检查剩余容量；定期巡检整理已完成内容，保护线阻止新启动并记录可恢复的存储等待，空间恢复后继续，不重置墙钟或用量。已启动工作有收尾预留；临界容量必须停止相关生产者并保留部分输出。工作区任意写入仍受巡检延迟影响，不宣称轮询等价于文件系统硬配额。

自动删除仅针对可验证的受管临时文件、读取缓存和无引用对象。正在使用的安装、冻结镜像、工作区、原生会话及研究证据不因年龄或分数删除。共享依赖清理须同时核对进程、构建锁与运行时引用；无法证明闲置则跳过。

工作台显示容量、活动用量、等待原因、近期净增长及预测是否有效。短观测窗口、零增长或整理导致的负增长不能伪造可靠的一周预测。外部归档由下述可选增量提供。

## 实施与验证

1. 内容存储、完整归档共享、证据及文件视图；检查多活动权限、摘要、幂等、发布失败和源文件变化。
2. 一致读取与分层快照；检查重复查询、局部更新、完整遍历、旧引用和事务一致性。
3. 分段压缩、读取及输出限额；检查跨段 Unicode、重启、损坏、用量对账和实际证据收集。
4. 自动巡检、受管回收、容量准入和展示；检查锁/使用者保护、低空间、恢复及未知状态保守处理。
5. 离线回归、无模型部署检查；同步远端后由用户执行长任务验收。各阶段通过相关检查后独立提交，不用真实模型成本替代工程检查。

2026-10-24 的增量验证覆盖累计超过 256 MiB 后继续写入、重开日志、跨段 Unicode 与摘要一致性、读取期间轮转，以及模型请求中发生磁盘写入失败后的根因保留。196 项 JavaScript、437 项 Python 单元检查和 17 项原生会话/网关契约通过，构建成功。另有两项既有契约测试分别仍依赖已移除的用量字段和旧审查目录，在修改前源码快照上复现相同失败；不计为通过。这些离线与模拟检查不代表现存冻结活动已升级或数日容量压力验收完成。


## 可选 NFS 归档（2026-10-25 增量）

宿主可显式配置 `archive-policy.json`，将已有共享格式的已关闭 Trial 大型原始结果和网关审计无损压缩到独立目录；默认未配置，不发生迁移。此增量允许运维在用户授权范围内归档历史，不更换旧活动冻结运行时，也不改变证据身份、官方评分或活动配置。源码、环境、Podman 镜像、活跃数据库、生产者输出及当前会话文件仍在本地。

归档的处理顺序是：确认生产者关闭且完整索引完成 → 本地不可变对象 → NFS 临时压缩文件 → 读回校验完整 SHA-256 和字节数 → 原子发布 → 本地定位索引和 NFS 对象回执 → 再校验后回收符合条件的本地硬链接。回执包含对象摘要、原始大小、相对路径和所属活动，可用于离线核验及重建定位关系。`archive-index.sqlite` 是本地 WAL 数据库；NFS 只保存关闭的普通文件。网络写入期间不持有全局对象锁或数据库写事务。

永久删除归档对象时，证据和历史来源按正文摘要、活动建立索引，查询其他活动的剩余引用；避免每个对象重新扫描全部历史证据。索引在控制数据库初始化时增量补齐，不改变正文、评分和活动配置。

第一版只归档至少 64 KiB、位于 `public_job_results` 的原始结果和 `gateway-audit.jsonl` 及其分段。官方结果、清单、会话恢复文件和正在写入的目录不迁移。未知硬链接、未结束活动已发布的 Meta 文件视图、最近一小时恢复/读取的对象阻止本地回收。已发布路径不能因腾空间而突然失效；活动结束后其视图可回收，后台读取会恢复对象和对应原路径。主机上的离线脚本须先运行显式恢复命令，不能假定已归档的原始目录仍有全部正文。

归档在低优先级独立进程执行，以本地 flock 防止重启后重复工作。默认上传速率 32 MiB/s、压缩后预算 200 GiB、远端最低剩余 10 GiB；这是应用预算，不代表用户拥有整个共享文件系统空闲容量，也不是文件系统硬配额。证据按需恢复在独立子进程执行，前台最多等待 30 秒；对象锁最多等待 5 秒。NFS 无响应时归档状态显示延迟，已归档证据读取明确失败，其他本地实验/控制请求继续可用。容量准入仍适用，网络不可用或活动引用增长过快仍可能令实验等待空间。

单活动永久删除先清理本地视图，再移除其远端归属和回执；共享对象保留到最后引用，NFS 清理失败不报告删除完成。归档根不允许直接切换到另一个位置，否则旧定位将不可用。回退不支持只切换旧程序：先禁用归档/回收、停止归档进程、将全部正文及路径恢复本地并核验，再切回旧版本；本地容量不足时继续使用支持归档的版本。

本地验证覆盖远端副本/回执失败、摘要损坏、缺失对象、阻塞恢复超时、对象锁超时、共享所有权、活跃视图、未知硬链接、目录逃逸、重启读取及官方元数据不变。217 项 JavaScript、537 项 Python 检查、10 项网关/传输/请求恢复契约、构建和依赖边界检查通过。TensorTrain 2 的独立发布目录通过 14 项归档专项检查、6 项真实 NFS 跨文件系统场景，并对历史原件完成复制、回收和同摘要恢复；归档前后历史业务表摘要一致。同设置新活动已启动主线与原生参考实验，完整 12 小时和长期容量验证仍在进行，不把启动验证当成长时间容量保证。
