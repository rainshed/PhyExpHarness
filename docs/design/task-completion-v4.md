# 任务完成规则 v4：已结束未评分尝试计失败

`harbor-process-v1` 的结果来源补充：可信官方分数可以与非零退出、AgentTimeoutError 或不完整诊断并存；收集器不再要求 turn completed 或工具调用数。没有可信官方文件仍是 officialReward=null，v4 任务完成分照原规则派生。此次重构不改变分母、人工撤销例外、历史版本或已保存原件。

状态：已实施，通过单元、契约、构建与新旧工作台验证。产品依据为需求文档第 3.3 节；本增量衡量模型与执行 Harness 整条链路的任务完成率。

## 结果与原因

新活动默认冻结 `taskEvaluationRule: task-completion-v4`。官方 `score/officialReward` 与原始报告保持不变；没有可信官方评分仍保存 null。派生 `taskAssessment` 记录成功/失败、完成分、是否进入分母和原因。归因未知不能使已结束的尝试退出分母。

| 条件（依优先级判定） | v4 结果 |
|---|---|
| 排队、启动中或运行中 | 待定，不结算 |
| 已结束且有可信官方二元评分 | 官方 1 计成功，官方 0 计失败；后续清理故障不覆盖已有结果 |
| 进程状态仍待核实，尚无结束确认 | 待核实，不提前判失败 |
| 已确认未进入启动尝试，且无官方结果 | 未执行，单列，不进入分母 |
| 明确人工停止，且没有已确认的先行失败 | 取消，单列，不进入分母 |
| 其余已经启动并最终结束的尝试 | 失败，完成分 0，进入分母；保留失败阶段和原因 |

“进入启动尝试”使用后台 claim 时保存的 `startedAt`，包括启动后容器装配失败，不能要求模型已返回 token 才算一次尝试。预留记录、排队后取消、尚未开始的预算准入拒绝不算执行。官方有效结果本身优先于不完整的启动元数据。`unknown` 若带后台确认的 `finishedAt`，表示结果未知但尝试已结束，计失败；若没有结束确认则仍待核实。仍在重试归集的运行记录不会仅因官方缺分而提前结算；本增量不改变进程核实与收集重试策略。

计零范围包括模型输出异常、最终未恢复的连接/服务故障、容器与插件执行故障、评分器失败、收集/归档失败、执行中的账本/凭证/预算准入失败、自动截止或时限不足终止，以及结束后仍缺结果。评分丢失、失败原因未查清也计零，原因可继续调查。`request_cancelled` 本身不证明用户撤销；明确的 `user_stop` 才享有人工取消例外。已确认的异常输出或发生在停止请求之前的故障，不能通过后续人工停止移出分母。

## 聚合、展示与历史

逐任务成功率 = 官方通过次数 / 纳入的已结束尝试次数。沿用任务等权聚合；完全没有纳入尝试的任务仍显示未测或待定，不给它凭空补零。保留全部重复尝试和失败，不用官方已评分比例替代任务成功率。

前端、报告、Meta 查询、候选比较与版本选择统一使用后台派生结果。主结果优先显示“失败 · 评分器异常”“失败 · 结果缺失（原因待查）”等；官方未评分作为详情。失败原因保留在 `reason/failure`，不因为计零而伪称模型科学能力失败。计分与排查是两个独立问题。

v1/v2/v3 的判定和展示保持兼容；缺少绑定字段仍按 v1 读取。已创建活动、原报告、选择快照和冻结执行插件不回写，也不批量迁移。创建请求的幂等回放必须恢复原绑定版本，不能因默认值从 v3 切到 v4 而冲突或换版本。只有新活动缺省采用 v4，显式历史版本仍可验证读取。

## 实施与验收

1. 在公共 outcomes 模块加入 v4，不改旧分支；更新创建默认值、验证枚举和幂等兼容。
2. 共享诊断和报告主标签使用新结果，官方评分放详情；两套工作台使用同一投影，不另算分。
3. 验证所有终结故障、未执行/人工取消/待定例外、人工停止不抹除既有失败、可信官方结果优先、已结束未知与未结束未知、任务等权和版本统计。
4. 验证实际后台创建、状态、Meta、比较、报告及选择快照一致；新旧创建回放和历史文件摘要不变。覆盖官方结果收集及失败归集到统计，不新增真实模型调用。
5. 运行相关单元和契约、工作台构建、浏览器验证及依赖边界检查；通过后更新运行说明与本地开发记录。重启前确认没有在途工作，保留历史和环境。
