# 工作台 UI 模块化与版本管理

日期：2026-10-22 · 状态：设计与迁移已获授权，实施和验收待完成。

本文细化[总体实现方案](meta-harness-implementation.md#9-ui-信息架构与交互)的 UI 边界；[Studio 设计](meta-workbench-studio.md)负责该版页面与阅读体验；步骤与验收以[开发任务书](../plans/meta-harness-development.md#22-ui-模块化与经典版移除)为准。

## 1. 目标与迁移起点

每版 UI 都能独立新增、修改和移除，不成为其他 UI 的基础依赖。当前经典版与 Studio 并存，Studio 从经典目录引用共享源码；运行时独立卸载已验证，源码独立尚未完成。本次先提取公共客户端，让 Studio 独立，再删除经典版专属代码。迁移后默认 Studio，后续可注册其他设计方案。

页面和功能模块也允许替换或删除。界面删减不自动删除后台 API、实验或报告；默认工作台仍须满足需求中的完整操作路径。试验版可只提供部分页面，但须明确范围，不把缺失入口解释为后台能力不存在。

## 2. 包与依赖

| 部分 | 职责与边界 |
|---|---|
| 控制后台 | 持久状态、权限、预算、调度、计分和报告事实，不依赖 UI |
| `meta-workbench-bridge` | 单份宿主 API 桥，独立装配，保留认证和用户身份隔离 |
| `meta-workbench-client`（待新增） | API、契约、查询、命令、校验、取消及请求身份管理，不含 JSX、DOM、页面导航或样式 |
| `meta-workbench-ui`（按需） | 稳定且实际被复用的组件，可选使用，不承载后台规则 |
| Studio 及未来 UI | 各自宿主/客户端入口、导航、页面、交互、组件与作用域样式 |

依赖方向：各版 UI → 公共客户端；各版 UI 可选 → 公共组件 → 公共客户端。客户端经 HTTP 使用宿主桥，由桥访问后台。公共包不是独立宿主插件。

- 具体 UI 之间禁止源码、包和样式依赖；公共包禁止反向依赖具体 UI。
- 使用声明的包入口，禁止绕过 `exports` 引用其他包内部文件。
- React 使用宿主共享模块，构建遵循锁定的 dsh 约定。
- 公共客户端可以提供无界面的 React Hook，但不决定导航、抽屉或焦点。
- 展示格式化、表格、供应商表单和报告布局先归具体 UI；真实复用且接口稳定后才提取公共组件，允许试验版适度重复展示代码。
- 预算、计分与历史快照以后台为准；前端输入校验不能替代后台校验。

## 3. 页面与功能模块

每版按 `shell/`（导航与装配）、`features/`（概览、比较、实验、报告等）、`components/` 和样式等职责组织，不要求每个页面独立成包，不新增运行时插件框架。

公共客户端提供读取报告、读取证据、创建和控制活动等操作，UI 决定显示方式。读取报告不能自动切换页面，创建成功不能自动滚动；取消、请求身份和修订校验属于客户端能力，焦点和对话框开关属于 UI。

功能注册集中管理标识、标题与渲染入口。删除功能时删除注册、专属实现和测试并检查跨页入口；其他页面不依赖被删页面。默认版本的必需操作仍须可达。

## 4. 状态、草稿和样式

后台是活动、报告和用量的权威来源。卸载清理轮询、订阅和监听；过期读取不得覆盖另一活动或重开已关闭详情。切换、重连不自动重发写操作，不启动或恢复活动。

活动选择、页面、筛选、展开与布局状态使用版本独立命名空间。创建草稿带格式版本；Studio 可一次性复制旧草稿，保留旧键。未来跨 UI 共享须定义兼容格式或显式导入，不能无条件共写一个键。

草稿与创建请求身份一起迁移。相同规范化配置的失败重试保留原幂等键，修改配置或成功创建后使用新身份。刷新、版本切换与迁移不得把不确定结果变成新提交。供应商密钥草稿不持久化或跨版本传递。

样式限定在各版根节点；公共组件不依赖具体 UI 的全局样式。修改一版不影响其他版本布局。

## 5. 注册、构建与淘汰

受版本控制的简单 UI 清单记录可用版本、默认版本与对应包，启动器和构建器共用解析。只加载所选 UI 和一份桥，宿主导航只显示实际加载的面板。未知版本、缺失包明确报错，不静默回退。

同一设计的小改动用 Git 记录，需要并存比较的设计才建独立包。公共入口变化时同步迁移当前保留版本，暂不引入长期多版本 SDK 兼容框架。

淘汰版本时删除包、注册、依赖、构建引用和专属测试；历史留在 Git。删除非默认版本无需改其他 UI 源码；删除默认版本前指定有效替代。公共代码不能存放在待删 UI 内，用户状态和后台数据不随源码删除。

## 6. 可验证的约束

依赖检查覆盖相对导入、包导入、依赖声明、TS/TSX 和样式，拒绝 UI 间及公共层反向依赖。用临时合成 UI 验证清单扩展、选择、构建和移除，不长期保留第二套演示界面。

公共客户端验证取消、过期响应、修订、幂等、草稿迁移和错误保留；具体 UI 验证主要操作、模块、样式与键盘。经典包不可访问时仍能构建 Studio。生命周期检查确认面板释放不释放桥、不发送后台停止命令。

旧测试记录仅说明旧结构；迁移不能提前宣称完成。实现状态随检查更新，新运行命令验证后才写入运行说明。
