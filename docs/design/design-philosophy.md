# 项目设计哲学

PhyExpHarness 希望研究：在给定任务范围、固定 Solver 及其模型和调用设置的情况下，如何构建和优化一个 Harness，使它更好地帮助 Solver 完成任务，并让人理解这一改进过程。

## 以插件表达能力，以组合形成版本

我们遵循 DeepSeek Harness 的 “Everything is Plug-in” 原则，从一个最小可运行的执行 Harness 出发，由 Meta Harness 自主设计、开发和改进执行插件。

每个插件承载职责清楚、能够单独说明和调整的能力。Meta 可以根据任务表现和执行轨迹，新增、修改、替换或移除插件，探索不同能力之间的组合。具体的插件版本及其配置共同构成一个执行 Harness 版本。

在可比较的任务与运行条件下，我们通过实验评估不同版本的任务通过率，并结合重复执行的稳定性与资源消耗，寻找更有效的组合。研究方向、插件划分和实验安排由 Meta 自主决定。

## 插件化支持有针对性的优化

将不同能力组织成插件，使 Meta 能够围绕具体问题调整 Harness：明确需要补充什么能力、修改哪一部分，以及哪些已有能力可以继续复用。

插件的职责、依赖和协作关系应当清楚，使其可以在合法组合中被替换、移除和比较。插件划分服务于理解和改进能力，不预设固定的插件数量或粒度。

## 让进化过程可读、可解释

理解 Harness 如何演化，是项目的核心目标之一。

我们希望人能够沿着研究过程，看懂最初遇到了什么问题，为什么设计某个插件，它预期改变什么行为，实验中实际发生了什么，以及这些证据如何影响后续修改与版本选择。

插件为这种理解提供了具体的能力单元；版本之间的组合差异，使能力的增加、调整、协作和舍弃能够被清楚呈现。设计动机、实际行为和实验结果之间应当保持可追溯的联系，失败、回退与尚无结论的尝试也属于演化脉络。

组合表现更好，首先说明该组合在已测条件下取得了更好的结果。理解其中各插件的贡献及相互作用，还需要结合执行轨迹、对照实验、重复测试和必要的消融。解释应明确区分设计意图、观察事实和已有证据支持的效果。

## 对后续开发的指导

后续开发应同时服务于两个目标：帮助 Meta 找到更有效的执行 Harness，以及帮助人理解它为什么这样演化。

插件接口应支持清楚表达能力与依赖；版本管理应准确记录组合变化；实验应支持有效比较；研究记录应保留动机与判断的演变；界面和报告应先呈现容易理解的研究脉络，再提供深入核查的证据与实现。

我们希望最终积累的是既能帮助 Solver 完成任务，又能被人理解、检验和继续改进的执行方法。
