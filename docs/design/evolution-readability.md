## 1. 阅读目标与分层

人应能理解当前研究哪个问题、为何沿这个方向修改、实际发生了什么、为什么选择或继续验证某个版本，以及什么新证据可能改变决定。解释基于可核查事实和 Meta 显式提交的理由，不要求获取隐藏思维过程，也不把通顺的解释当作效果证明。

| 层次 | 默认回答的问题 | 内容边界 |
|---|---|---|
| 概述 | 现在在解决什么、发现了什么、当前选什么 | 独立可读的简短说明；关键局限与结论一起出现 |
| 解释 | 为什么值得尝试、观察支持到哪一步、如何取舍 | 观察、假设、修改目的、主要备选、代价、局限与下一步 |
| 依据与实现 | 哪次实验、哪段轨迹、哪个精确版本支持判断 | 定位片段、完整原文、事实快照、配置与冻结源码 |

逐版本逐任务成功率、成功数/纳入分母和在途实验进度是默认层的核心事实，不因有了概述而被折叠。研究转折与运行事件分别组织；并发、复测、回退和放弃均可存在，不把全部过程画成线性成功故事。

## 3. 研究记录及关联

### 3.1 公共身份与来源

研究记录使用 `evolution-research-v1`；以下规定语义，实际工具与存储映射见第 9 节。

- 每条记录有稳定 ID、schema 版本、修订、作者/来源、记录时间、所属活动，以及适用的事实时间或快照引用。补充历史解释时，记录时间与被描述事件的时间分开。
- `summary` 表达高层含义；详细解释保存观察、假设、取舍和局限。概述与详细解释属于同一修订，不能通过前端截断正文生成语义结论。
- 通过准确身份关联插件内容、候选、批次、Trial、报告修订和选择决定；未产生候选的尝试可以只关联研究记录或草稿身份。冻结后记录实际内容摘要，不能把后续草稿冒充当时版本。
- 证据引用指向已经核验的来源，模型提交的文字不覆盖官方结果、计分、时间、用量或运行状态。后台校验完整性、归属和引用关系，不认证自由文本推理正确。
- 新认识追加修订或关联记录，不覆写旧判断。读取时标明当前解释及其事实范围；历史报告引用具体修订，不自动取最新研究解释。

### 3.2 改动动机与尝试

记录要解决的问题、问题出现在哪些允许来源中、为何值得尝试、计划改变什么行为、希望用什么观察检验，以及主要未知项。没有直接失败轨迹的探索可以说明来自一般假设或已有研究，不强迫伪造证据。

记录可以在提出方向时创建，形成候选、验证或放弃后补充关联；不要求每次编辑先经过固定分析流程。冻结候选时携带或关联动机记录，多个插件可以对应同一个尝试；同一插件也可以在不同活动中因不同问题被采用。装配失败和未冻结的尝试保留结果，不能因缺少候选 ID 而消失。

插件清单继续描述通用用途、接口与行为。活动内的开发理由、轨迹、分析和历史经验存于研究记录，不随插件复制到 Solver 执行上下文或独立项目。说明修订不改变冻结插件摘要。

插件清单可提供 `categories` 多选阅读分类：`prompt-context`（提示与上下文）、`tools`（工具能力）、`tool-results`（工具结果处理）、`execution-control`（执行控制与恢复）、`other`（其他扩展）。缺失分类明确待补充，不能根据名字或权限声明猜测。`functionSummary` 回答做什么，`mechanism` 用普通中文回答如何做到、何时作用、产出及必要限制，不以接口列表替代说明；不新增行为类型枚举。说明是设计用途，不是已验证效果。

读取投影保留分类和说明来源。旧插件可按准确内容身份通过已有说明补充机制整理，并记录作者、时间及冻结源码依据；不修改旧清单、内容摘要或历史报告快照。插件详情默认先读用途和机制，再读动机、观察、使用版本和实现。版本对比展示所选版本的完整组成及对应任务表现，变化过程仍由独立进化记录承载。

**代码继承、证据启发、实际使用是三种关系。** `parentId` 只说明候选的代码来源；某条历史轨迹启发了新插件，不表示两个候选存在父子关系，也不表示历史活动的成绩属于新候选。

### 3.3 验证观察与认识变化

每轮分析可关联对应尝试，说明想确认什么、实际观察什么、哪些认识变化，以及下一步。插件观察关联准确的插件内容身份和实际实验，区分加载、适用条件出现、触发、行为变化和任务收益；无法观察时为未知，有足够记录确认未触发时才写未触发。正常成功不能替代恢复机制被检验的证据。

原 `process/problems/pluginContributions` 兼容读取；新契约补充可定位身份和认识关联，不能仅凭插件显示名将不同内容版本合并。报告引用后台事实快照，研究记录引用报告修订，形成可核对的闭环。下一步是 Meta 的计划或待验证问题，是否已排队、启动或取消仍由 Batch/Trial 事实决定。

### 3.4 选择与主要备选

扩展现有选择契约及存储，保留 `reason/tradeoffs/limitations/reconsiderWhen`，补充独立简短结论和明确考虑过的备选候选、未选原因及相应依据。没有明确备选分析时显示未记录，不能将全部未选版本自动标为已否决；基线或首次选择可以没有备选。

平台在决定时冻结被选版本、此前版本及明确纳入比较的备选事实与统计范围，记录无结果、不同条件和缺失成本。选择写入与决定记录保持事务一致，沿用幂等键与预期修订。后续结果、改名和新解释不改写当时事实与理由；维持或回退也是新决定。页面可同时展示最新表现和历史理由，但必须标明各自时间。

## 4. 写入与生成职责

Meta 通过业务接口提交研究解释；提交能力可复用或扩展现有冻结、报告和选择工具，必要时增加轻量研究记录操作。接口细化不得变成固定的多 Agent 研究流水线或固定改进算法。

后台负责校验、事务、归档和读取；可用模板描述确定性状态，不代替 Meta 发明动机或原因。简短职责进入 `src/control/prompts/meta-system.md`，字段说明和样例按需提供，完整长记录不常驻启动上下文。

概述随相关研究或报告操作生成并持久保存，不在每次打开页面或轮询时调用模型。新增分析调用遵循同一活动预算、角色与截止规则；预算不足或会话中断时保存已有事实和解释缺项，不为补齐文案自动延长活动。

新 schema 与工具契约需要版本化。当前 `meta_contracts.py` 会核对冻结工具绑定，不能直接改变当前契约文件后让旧活动解析最新 schema。实施时保留旧协议及精确资产的解析路径，为新活动绑定新版本；旧记录读取适配与运行协议升级分别处理。重启和重试不重复创建研究记录、候选、决定或报告。

## 5. 判断到证据的路径

### 5.1 片段定位

在原证据 ID 之上保存内容摘要及定位信息，例如事件索引、JSON 路径或明确单位的字符范围，并保存“这段材料支持什么判断”的说明。后台根据原件检查范围与摘要，返回原始上下文及全件入口；位置失效、格式不支持、源文件缺失或无权访问分别展示，不能跳到无关片段冒充依据。

关键判断各自关联证据，不仅在页面末尾列一串“证据 1、2、3”。先展示版本、任务、实验、事实时刻、相关片段及支持范围，再按需展开完整原文。用户阅读入口与 Meta 可访问材料遵循各自角色和同一来源策略，页面可见不自动扩大模型权限。

### 5.2 跨活动问题来源

当前材料目录、Meta 查询和选择证据以单活动为边界。目标方案通过显式历史材料纳入记录支持“先前哪个项目/活动中的哪个问题促成这次修改”，不直接放开任意跨活动 ID 或宿主目录。

纳入记录至少保存来源项目/活动、候选与 Trial（有则保留）、原证据/报告修订身份、内容摘要、纳入时间、目标活动及可访问范围。仅在目标活动已允许的来源与任务用途范围内建立可核验的本地引用或受控材料副本；原身份、转换关系和限制保留。当前 `evidenceRefs` 规则继续拒绝未经纳入的其他活动原始 ID；新协议使用目标活动内的受控引用解析到来源。候选选择对象仍属于当前活动。

历史来源按“设计启发”标识，只有明确可用时才展示片段。原始执行证据与旧报告分析分别标注，不能把旧分析升级为官方事实；来源不可用时保留已知身份并说明缺失。纳入历史材料不会导入 Trial 成为当前成功率样本，也不改变当前成绩、预算或旧活动。任务反馈暴露历史继续追踪，不能将已用于优化的材料重新称为未见评估。

历史来源支持属于目标功能；分期未接入时明确显示范围限制，不能以同活动路径通过代替跨活动能力已完成。历史内容整理另有明确范围和修订来源，平台不自动导入或回填历史活动；用户通过明确的来源纳入和追加解释操作完成。

## 6. 读取视图与统计

后端基于事实、研究记录、选择决定和报告修订组织面向阅读的视图。概览提供研究摘要、当前选择、版本/任务表现、关键转折和下一步；插件与选择详情按需读取具体解释。事实统计继续复用 `outcomes.py` 和 `tables.py`，不新增一套计分逻辑。

响应包括读取/事实时间、来源记录 ID、修订和完整性状态。关键转折来自显式研究记录及真实关联，不把每个运行事件自动解释为认识变化；原轮次和全部失败仍可直接查找。没有解释时显示缺项并保留事实入口。

摘要查询有明确范围和条数，历史列表可分页；证据、完整分析、候选配置和源码按需读取，不随两秒轮询反复传送全部正文。新读取接口经现有宿主桥与公共客户端接入；不把叙事存储、业务规则或导航挪进桥。

任务矩阵读取后台提供的成功数、纳入分母与规则版本；状态数量来自同一范围的 Trial。未测试、运行但无完成结果、失败、取消、未确认结束分别呈现。成本保留统计范围、记录覆盖和未知用量；平均与合计、单次耗时相加与活动墙钟分开。历史报告/决定使用其绑定快照，不能与实时试验混算。

## 8. 历史兼容与实施边界

旧活动缺少结构化动机、备选或片段时，读取已有理由、报告与证据并明确未记录，不在读取时生成新模型分析。后续经授权整理时追加有作者、时间和来源的新修订，不替换原件、旧判断、原始评分或既有选择。历史解释可以被补充，不能倒写成当时已经存在。

分期按任务书第 23 节推进：先利用现有事实改善页面，再形成新活动的研究解释闭环，最后接通跨活动来源与有来源的历史整理。每期声明实际范围，参考演示的合成文案不得用于填充真实活动。对布局、摘要长度和大量版本/任务的展示方式可以调整，但不能隐藏逐任务表现、关键局限、失败或证据入口。

## 9. 已落地的契约与接口

### 9.1 新活动与旧活动

新活动冻结 `meta-tools-v4`、`meta-report-analysis-v2`、`evolution-research-v1` 和 `meta-tool-receipt-v1` 的精确资产摘要。原 v3 五份契约/渲染资产保存在 `packages/meta-harness/protocols/meta-tools-v3/`，原 v3 活动按原资产解析；无绑定的历史 v2 仍走兼容入口。摘要不符或未知版本拒绝恢复，不自动升级。数据库 schema 4 只增加 `research_records`、`research_links`、`source_adoptions`，不改写既有记录。

`research_save` 提交 `record`、`expectedRevision`、`idempotencyKey`，更新时另带稳定 `recordId`。新建预期修订为 0，成功生成修订 1；后续追加新行。`kind` 为动机、观察、转折或补充说明，`state` 为提出、验证中、有支持、无结论、失败或放弃。概述至多 600 字符；正文包含问题、假设、改动、验证、局限、下一步和事实时间。作者与记录时间由后台赋值，事实时间不能在未来。各修订、引用和写回执均可重放，不依赖页面实时生成说明。

`candidate_freeze.researchRefs` 关联准确研究修订与实际冻结内容；数组可空，缺解释如实显示。`candidate_retain` 新增必填 `summary`、`alternatives`、`researchRefs`，保留原字段、预期选择修订和幂等键。备选可为空，不能把全部未选版本自动认定为拒绝。后台在同一事务保存选择、研究修订和选定/此前/显式备选的候选身份、当时名称、全部尝试、统计与账本用量。报告 v2 新增必填 `brief`、`researchRefs`；报告保存事实快照中的解释修订，离线 Markdown 也呈现概述、解释、备选及局限。

### 9.2 片段、读取与历史来源

| 接口/工具 | 范围与返回 |
|---|---|
| Meta `research_list` / `research_read` | 分页摘要 / 准确修订；返回紧凑业务回执及完整材料路径，研究角色可只读访问 |
| Meta `evidence_excerpt` | 核验原件摘要和 Unicode 字符区间，返回相关片段、上下文及原文偏移 |
| `GET /campaigns/{id}/research?offset=&limit=&pluginKey=&relation=` | 最新研究修订摘要，默认 20 条、最大 50 条；可按准确插件身份和关联类别在分页前筛选，包括来源、时间和读取指纹 |
| `GET /campaigns/{id}/research/{recordId}?revision=` | 单修订正文、修订目录、准确候选关联与片段核验结果 |
| `POST /campaigns/{id}/research` | 用户署名追加解释；事后整理必须关联原报告、片段或既有研究记录 |
| `POST /campaigns/{id}/excerpt` | 用户按需核对证据片段；不会扩大 Meta 的来源范围 |
| `GET /campaigns/{id}/selections/{decisionId}` | 单条决定的完整历史快照，主状态轮询只传简短说明与可读标识 |
| `GET/POST /campaigns/{id}/sources` | 查看或显式纳入其他活动的证据/报告；仅用户可写 |
| `GET /campaigns/{id}/sources/{sourceId}?offset=` | 读取受控副本，保留来源分类、身份、摘要和字符分页 |

片段采用 `{evidenceId,sha256,start,end,unit:"characters",supports}`，`end` 不含尾字符，单段至多 16,000 字符。摘要失效、范围错误、格式不支持、无权访问、缺失原件分别返回状态。历史来源输入为 `sourceCampaignId/sourceKind/sourceId/reason/access/idempotencyKey`；`sourceKind` 为 `evidence` 或 `report`，`access` 默认为前端选择的 `user-only`，用户可明确选 `meta-research`。只有后一种在目标活动生成受控证据引用并挂载到 Meta/研究材料；Solver 和执行导出不接收这些材料。

来源须属于平台允许的公开开发证据策略，来源任务不得超出目标活动任务集。旧报告按分析材料纳入，携带原作者、修订与事实摘要；不当作官方执行证据。受控副本在来源文件后续缺失时仍可核验，副本本身缺失或损坏则明确不可用。历史成绩不导入当前 Trial，当前成功率、成本和预算不受纳入操作影响。

### 9.3 前端接入和已知边界

公共客户端承担查询、取消与过期响应隔离；主状态只携带研究记录/关联数量指纹，变化时重新读取有限摘要页。完整说明、选择快照、证据和源码按需读取，页面轮询不触发模型。概览依次呈现已保存的研究结论与选择、实时矩阵、关键研究节点和下一步；插件页以单个准确内容版本为阅读对象，按动机、观察、取舍、实现逐层展开。实验每页 20 条，研究摘要每页 20 条，决定每次增加 10 条，轮次每次增加 20 条。

研究摘要的插件关联同时包含记录声明、结构化观察和冻结候选关联。可选 `pluginKey` 筛选在分页前执行；`developmentRefs` 返回候选冻结时绑定的研究修订。筛选时另返回 `pluginContext`，包含最早开发/采用关联的 `developmentRef` 与最新观察摘要 `latestObservation`，两者不受当前摘要页影响。插件开发动机优先读取该准确修订，不因后续解释更新替换原来动机，也不会被大量后续记录挤出首页。它们属于用户只读投影扩展，不修改 Meta 写入契约或旧活动的冻结绑定。

「查看全部研究记录」是独立的次级入口，不作为插件卡片。进入后按 `relation=plugin`（存在准确插件关联）和 `relation=unlinked`（尚无插件关联）分组；未指定时沿用全部记录。`relationCounts` 返回分类筛选前、当前插件范围内的两类总数，各类独立分页。分组不推断成功或失败，也不改写研究状态；后续新增插件关联时，相应记录自然转入相关研究一类。

当前定位单位是 Unicode 字符，不承诺 JSON 路径或事件索引定位。未提供普遍可靠的测量/评分细阶段，沿用实际状态。解释是作者提交的研究判断，平台校验身份与来源，不认证因果收益。旧活动缺失说明不自动生成；旧报告原件及旧编号保持原样，新报告沿用活动的版本编号。
