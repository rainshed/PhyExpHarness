# 新工作台 UI 插件设计

日期：2026-10-19 · 范围：独立 UI 插件、共享后台桥、新旧并存与安全切换

本设计落实新工作台的交互原型方向，继承[总体架构](meta-harness-implementation.md#9-ui-信息架构与交互)与[产品要求](../requirements/meta-harness.md)。原型样式参考 Claude Opus 5.5 的设计建议，功能和运行语义以现有代码、接口和需求为准。演示数据不进入正式插件。

## 1. 目标与边界

新增 `@phyexp/meta-workbench-studio`，保留 `@phyexp/meta-workbench` 作为经典界面。新插件接入同一个控制后台，能够创建和操作活动、浏览全部实验记录、阅读报告与证据、配置供应商和取得独立项目。不是独立 Web 应用，不实现第二套调度、预算或模型循环。

把旧插件的 `/phyexp/api` 路由拆为独立的 `@phyexp/meta-workbench-bridge`。运行时只装配一份共享桥；新旧 UI 的宿主入口不再拥有该路由。卸载任一 UI 不卸载共享桥，也不向控制后台发送停止命令。桥继续复用原生会话认证、可信来源、Origin、路径白名单与后台用户凭据隔离。

## 2. 包与依赖

| 包 | 职责 | 生命周期 |
|---|---|---|
| `packages/meta-workbench-bridge/` | 固定宿主 API 桥 | 随 UI 宿主，不随面板 |
| `packages/meta-workbench/` | 经典 UI、共用客户端控制与业务组件 | 独立客户端面板 |
| `packages/meta-workbench-studio/` | 新布局、导航、概览与详情抽屉 | 独立客户端面板 |

两个 UI 使用同一客户端控制 Hook、配置校验、模型能力、供应商设置、任务统计、失败诊断、三表、报告、证据和导出组件。共享代码在构建时打入各自客户端包，React 仍使用宿主共享模块。新包对经典包的源码依赖不是运行时对经典面板的依赖。

新旧面板分别注册 `phyexp-workbench-studio` 与 `phyexp-workbench`，导航入口名称和标识不同。样式限定在各自根节点内，不修改宿主或另一插件的样式。活动选择和活动草稿沿用同一浏览器存储键；展示页签、抽屉与步骤属于各面板局部状态。后端始终是活动状态的唯一权威。

## 3. 页面与信息架构

稳定左栏包含活动选择、新建活动、局部页面导航、供应商设置和旧界面入口。顶部显示活动位置与真实后台连接状态。暖白背景、石墨文字、细分隔线和克制青绿强调用于区分层级；窄窗口堆叠内容，表格局部横向滚动，键盘焦点保持可见。

| 页面 | 默认内容 | 完整功能入口 |
|---|---|---|
| 概览 | 当前工作、已受理轮次、实验数量、已确认用量、耗时、当前保留与最新版本、近期轮次 | 启动、暂停、恢复、停止、调整上限、配置、选择依据、总报告 |
| 实验工作区 | 插件 / 执行版本 / 实验轮次子标签 | 源码与声明、版本改名、配置与血缘、跨表定位、复测分组、逐次故障、单次终止、证据和报告 |
| 研究报告 | 报告列表与修订、结论优先的正文 | 过程、问题、插件贡献、决定与局限、消耗、原分析、三表、证据抽屉与下载 |
| 证据库 | 编号、类型、实验关联与字节数 | 正文抽屉、稳定身份、字符偏移分页 |
| Meta 运行 | 冻结组合、加载与触发、停止审查、后台动态 | 会话状态、错误、事件、缺失证据、下一方向与审查用量 |
| 获取 Harness | 默认最终或保留版本、组成与真实结果 | 生成、下载、打开目录、运行说明、独立装配及三层验证 |
| 供应商与模型 | 现有真实供应商设置组件 | 认证、协议、模型能力、兼容参数、未保存保护、显式测试与独立用量 |

新建活动分为目标与两模型、开发任务、额度三个步骤，最终仍使用现有完整校验和创建接口。允许返回修改，不提前创建后台活动；创建与启动分离。模型目录以后台为准，支持回到设置管理并保留草稿。

## 4. 必须保留的语义

- 轮次按受理批次计数，包含 H0；已启动、在途、待执行实验分别呈现。
- 官方科学零分、未评分、外部失败、取消、待归因不能混为同一数值。任务等权统计与保守统计沿用后台投影。
- 最新候选、当前保留、最终冻结分开；保留决定是 Meta 的取舍，不是平台认证因果提升。
- 暂停不冻结墙钟；停止受理不等于外部终止确认；断线状态可能陈旧，不能显示为后台停止。
- 已确认、在途预留、未知用量和收尾预留分别显示。没有可靠金额硬上限，不新增虚假的费用控制。
- 报告展示修订不覆盖原始分析；证据正文按字符偏移读取，渲染文本不能执行脚本或后台操作。
- 导出三层状态为文件完整性、独立安装与加载、独立真实实验。下载不隐式启动实验；装配通过不等于实跑通过。

## 5. 切换、卸载与恢复

启动器支持 `PHYEXP_UI_VARIANT=both|studio|classic`，默认 `both`。三种模式都加载共享桥，之后只装配所选 UI。两面板并存时通过原生布局导航即时切换。UI 不自动启动或恢复活动，不自动调用供应商测试。

面板卸载时清理轮询和客户端监听，忽略已失效的异步读取；报告与证据不得在切换活动后串入另一个活动。重新挂载从后台重建状态。写请求保持现有 revision 和幂等键语义，不在重连或重挂载时自动补发。

“即时切换面板”和“宿主动态卸载/加载插件”分别验证。宿主原生插件生命周期允许动态移除贡献；配置方式切换可重启 UI 宿主，后台和实验保持运行。不要把代码文件改动宣传为自动热更新；重新构建后按宿主要求重新加载。

## 6. 验证与交付

1. 单元/契约：单份共享桥、认证边界、独立面板标识、注册与释放、事件游标、异步竞态、配置校验、跨表定位。
2. 浏览器：真实构建包加载到原生宿主，七个页面与新建/额度/证据/源码/导出/供应商入口；键盘抽屉、中文长文本、窄窗口。
3. 生命周期：重复挂载、切换新旧、卸载新 UI、重载与重连，后台记录不被修改、不重复启动实验。
4. 全仓既有检查：构建、单元、契约和依赖边界；失败须定位，不把 UI 变更转化为新科学实验授权。

合成夹具、真实后台只读检查和真实模型实验分别记录。本次不为验证外观重跑科学实验。检查记录存放在本地 `reports/development/meta-harness/`，正式文档不依赖该目录。

## 7. 本次实现与验收范围

已实现独立 Studio 包、共享桥、经典 UI 保留、共用客户端业务，以及三种启动模式。构建、单元、契约和依赖边界检查通过。原生宿主浏览器联调覆盖活动创建、暂停恢复、跨表定位、源码、改名、报告与证据分页、导出下载、供应商草稿保护、新旧面板切换和窄屏。另对既有活动进行了只读检查。

`tests/contracts/workbench-lifecycle.test.mjs` 使用原生 Cordis 生命周期验证 UI 贡献释放、重新注册和共享桥独立存活；`tests/contracts/workbench-access.test.mjs` 对三种启动模式分别验证宿主认证和请求边界。浏览器验证实际面板切换与刷新恢复；没有把插件管理器中的人工启停操作或源码自动热更新列为已验证能力。

界面关闭会取消轮询；活动切换、抽屉关闭和卸载后，过期读取不能重新打开旧证据或源码。证据分页时即使按钮暂时禁用，Escape 仍可关闭抽屉并回到阅读位置。本次只用隔离夹具验证写操作，没有为 UI 验收发起真实模型实验。
