## 1. 目标与边界

保留 `@phyexp/meta-workbench-studio` 作为默认界面，经典版已移除。Studio 接入独立控制后台，能够创建和操作活动、浏览全部实验记录、阅读报告与证据、配置供应商和取得独立项目。不是独立 Web 应用，不实现第二套调度、预算或模型循环。

`/phyexp/api` 路由已由独立的 `@phyexp/meta-workbench-bridge` 提供。运行时只装配一份共享桥；各版 UI 的宿主入口不拥有该路由。卸载任一 UI 不卸载共享桥，也不向控制后台发送停止命令。桥继续复用原生会话认证、可信来源、Origin、路径白名单与后台用户凭据隔离。

## 2. 包与依赖

| 包 | 职责 | 生命周期 |
|---|---|---|
| `packages/meta-workbench-bridge/` | 固定宿主 API 桥 | 随 UI 宿主，不随面板 |
| `packages/meta-workbench-client/` | 公共查询、命令、校验和请求身份 | 构建依赖；读取随消费者清理 |
| `packages/meta-workbench-studio/` | Studio 页面、导航、交互与样式 | 独立客户端面板 |

Studio 通过公共包导出使用客户端能力；页面和展示组件归 Studio 自己维护。共享客户端构建进各版 bundle，React 使用宿主共享模块。其他 UI 不得引用 Studio 内部文件。

Studio 注册 `phyexp-workbench-studio`，样式限定 `.studio-root`。活动选择、草稿与待重试请求使用本版 v1 存储记录；旧键仅在首次迁移时读取并保留。页签、抽屉与步骤为面板局部状态，后台是活动状态的权威来源。

## 3. 页面与信息架构（第二版已批准）

稳定导航包含活动选择、新建活动、局部页面导航、供应商设置；其他已加载版本通过原生宿主导航进入。顶部显示活动位置与真实后台连接状态。以自然语言回答“现在怎样、哪个版本更好、依据是什么、下一步做什么”；用字号、行距和分组区分层级，不能仅靠颜色。桌面保留侧栏，窄窗口收为菜单；报告正文优先获得可用宽度。暖白与石墨为明亮主题基调，青绿用于少量强调；同时提供可读的暗色主题。

| 页面 | 默认内容 | 完整功能入口 |
|---|---|---|
| 活动概览 | 运行与分析状态、当前保留与最新版本、当前工作、用量与限制、下一步 | 启动、暂停、恢复、停止、调整上限、配置、选择依据、近期轮次 |
| 版本对比 | 默认基线与当前保留版本，按任务比较结果、覆盖与成本 | 加入候选、对比条件、逐次结果、版本改名、配置与血缘、保留决定 |
| 实验记录 | 按轮次排序的紧凑摘要；展开一轮后看任务与逐次实验 | 复测分组、逐次故障、单次终止、版本变化、报告和上下文证据 |
| 研究报告 | 结论、任务对比、收益与代价、局限；列表显示明确轮次、时间与修订 | 过程、插件贡献、原始分析、三表、证据和下载收于详情或附录 |
| 运行详情（二级入口） | Meta 会话、冻结组合、加载与触发、停止审查、资源规划 | 错误、事件、缺失证据、下一方向、审查用量与高级证据检索 |
| 插件与配置（二级入口） | 执行插件职责、人类可读的配置摘要 | 源码、声明、依赖、冻结身份、配置差异与完整标识 |
| 获取 Harness | 默认最终或保留版本、组成与真实结果 | 生成、下载、打开目录、运行说明、独立装配及三层验证 |
| 供应商与模型 | 现有真实供应商设置组件 | 认证、协议、模型能力、兼容参数、未保存保护、显式测试与独立用量 |

新建活动分为目标与两模型、开发任务、额度三个步骤，最终仍使用现有完整校验和创建接口。允许返回修改，不提前创建后台活动；创建与启动分离。模型目录以后台为准，支持回到设置管理并保留草稿。

“证据库”从主导航移除，证据从结论、任务结果和失败原因旁的“查看依据”进入；高级检索保留在运行详情中。此调整只改变入口与呈现，不删除证据、原始记录或下载能力。

## 4. 必须保留的语义

- 轮次按受理批次计数，包含 H0；已启动、在途、待执行实验分别呈现。
- 官方科学零分、官方缺分和故障原因分别保留。任务等权统计采用后台绑定规则；v4 已结束外部故障及结果缺失计失败，未执行、人工撤销及未确认结束单列。
- 最新候选、当前保留、最终冻结分开；保留决定是 Meta 的取舍，不是平台认证因果提升。
- 暂停不冻结墙钟；停止受理不等于外部终止确认；断线状态可能陈旧，不能显示为后台停止。
- 已确认、在途预留、未知用量和收尾预留分别显示。没有可靠金额硬上限，不新增虚假的费用控制。
- 报告展示修订不覆盖原始分析；证据正文按字符偏移读取，渲染文本不能执行脚本或后台操作。
- 导出三层状态为文件完整性、独立安装与加载、独立真实实验。下载不隐式启动实验；装配通过不等于实跑通过。

## 5. 切换、卸载与恢复

启动器读取 UI 清单，默认只加载 Studio 和一份共享桥。可选择清单内版本或全部版本；具体命令见运行说明。其他版本加入后，通过原生宿主导航切换。UI 不自动启动或恢复活动，不自动调用供应商测试。

面板卸载时清理轮询和客户端监听，忽略已失效的异步读取；报告与证据不得在切换活动后串入另一个活动。重新挂载从后台重建状态。写请求保持现有 revision 和幂等键语义，不在重连或重挂载时自动补发。

“即时切换面板”和“宿主动态卸载/加载插件”分别验证。宿主原生插件生命周期允许动态移除贡献；配置方式切换可重启 UI 宿主，后台和实验保持运行。不要把代码文件改动宣传为自动热更新；重新构建后按宿主要求重新加载。

## 6. 验证与交付

1. 单元/契约：单份共享桥、认证边界、独立面板标识、注册与释放、事件游标、异步竞态、配置校验、跨表定位。
2. 浏览器：真实构建包加载到原生宿主，覆盖主要页面、次级页面及新建/额度/证据/源码/导出/供应商入口；键盘抽屉、中文长文本、窄窗口。
3. 生命周期：重复挂载、切换已注册版本、卸载 UI、重载与重连，后台记录不被修改、不重复启动实验。
4. 全仓既有检查：构建、单元、契约和依赖边界；失败须定位，不把 UI 变更转化为新科学实验授权。

合成夹具、真实后台只读检查和真实模型实验分别记录。本次不为验证外观重跑科学实验。检查记录存放在本地 `reports/development/meta-harness/`，正式文档不依赖该目录。

## 7. 第一版实现与验收范围（历史记录）

已实现独立 Studio 包、共享桥、经典 UI 保留、共用客户端业务，以及三种启动模式。构建、单元、契约和依赖边界检查通过。原生宿主浏览器联调覆盖活动创建、暂停恢复、跨表定位、源码、改名、报告与证据分页、导出下载、供应商草稿保护、新旧面板切换和窄屏。另对既有活动进行了只读检查。

`tests/contracts/workbench-lifecycle.test.mjs` 使用原生 Cordis 生命周期验证 UI 贡献释放、重新注册和共享桥独立存活；`tests/contracts/workbench-access.test.mjs` 对三种启动模式分别验证宿主认证和请求边界。浏览器验证实际面板切换与刷新恢复；没有把插件管理器中的人工启停操作或源码自动热更新列为已验证能力。

界面关闭会取消轮询；活动切换、抽屉关闭和卸载后，过期读取不能重新打开旧证据或源码。证据分页时即使按钮暂时禁用，Escape 仍可关闭抽屉并回到阅读位置。本次只用隔离夹具验证写操作，没有为 UI 验收发起真实模型实验。

以上验收针对第一版，不表示下列第二版方案已经实现或通过检查。

## 8. 阅读问题与改版要求

本节保留第二版的改版依据和比较默认值；2026-10-22 分层阅读的新增目标与调整以第 14 节为准，不将本节历史默认值当作新的实现要求。

### 8.1 轮次摘要与详情分离

现状中，轮次、版本、结果三列共用一行高度，右侧长报告和逐次结果撑高整行，左侧出现大片空白；右侧内部又过密，窄窗口必须横向寻找结果。

- 默认一轮只展示轮次、版本、简短变更、任务覆盖、结果状态及报告入口。不要把完整报告、重复统计、故障列表塞入同一表格行。
- 展开后按“变更摘要 → 任务结果 → 逐次实验”阅读。复测可分组，但每次实验的身份、归因、成本、证据和终止入口仍可达。
- 详情占内容区完整宽度。手机改为纵向结构，不保留三个互相挤压的长列。
- 默认按轮次降序，明确时间与排序方式；展开或返回后保留阅读位置。报告跳转应定位对应轮次和修订。

### 8.2 研究报告先支持判断，再支持追溯

- 正文顺序：**结论与决定 → 基线/保留版本的逐任务表现 → 成本与代价 → 局限和下一步**。结论必须有依据入口。
- 区分完整研究报告与“阶段摘要 · 分析未完成”。后台已结束但分析中断时，两种状态分别展示；不能以绿色“成功”或“进化总报告”暗示分析完毕。
- 缺少分析时，仅提示一次缺失范围，展示已确认的事实，不补写未经分析支持的结论。
- 插件贡献仅展开有证据的变化与影响；无记录的多项插件合并为一句提示，完整插件清单仍可查阅。
- 原始分析、三表、事件、Meta 诊断、保留历史和长故障日志放入可展开附录，避免重复正文。
- 报告列表以轮次和时间明确排序，默认展示该轮最新修订，保留切换旧修订和下载。报告标题配一句内容摘要，不只展示编号。
- 正文保持舒适行长与行距，不用大面积等宽文本代替报告；长编号、路径与机器字段只在技术详情中展示。

### 8.3 成功率按版本和任务计算

主视图必须能回答“哪个版本在哪些任务上变好或变差”，不能把所有历史版本混成一个性能指标。

1. 默认比较基线与当前保留版本，可增加最新候选或指定版本；明确最新、保留、冻结三种角色。
2. 比较矩阵按任务列出各版本的成功率与**成功数 / 纳入分母的实验数**，同时显示覆盖情况、小样本提示和成本。百分比不得脱离分母。
3. 沿用活动自身的计分规则和后台 `byCandidate`、`byTask` 投影。官方零分与按规则记零均可能进入分母，但必须区分原因；v4 已启动并结束的未评分与外部故障计零，只有后台明确排除的未执行、人工撤销和待定单列。前端不得自行统一不同活动的归因规则。
4. “未测”及尚未结束的待核实结果没有成功率。v4 已启动并结束的未评分/原因未明结果按后台派生失败计 0，允许显示 0%；不修改官方分数。历史 v1/v2/v3 沿用原投影。
5. 聚合指标为次要信息；任务等权与按实验加权不能混称。只有选择范围满足覆盖和计分要求时，才显示该范围的任务等权值，并明确任务数及范围。
6. 比较条件包含任务及其修订、模型、评估规则、预算与运行环境。条件不同的版本默认排除；显式加入时标为“条件不同，仅供参考”，不得参与同条件提升量或排序。关键条件缺失时显示“可比较性待确认”，不能把缺少记录当作条件相同。
7. 有缺失任务时，默认保留完整任务集和缺失状态；用户可切换到共同已测且可评分任务，必须同时展示范围缩小和覆盖警告。不能悄悄以子集代表全部任务。
8. 成本、耗时与结果并列提供，但明确统计范围、已确认/未知状态以及均值或总量；不把更高预算下的提升描述为免费提升。
9. 跨版本总成功率如保留，只放在运行历史统计，并标注它不能代表某一版本的能力。
10. 保留版本是 Meta 的取舍，低样本观察不等于显著或因果提升。报告不得凭演示数据暗示真实科学结论。

### 8.4 证据回到阅读上下文

证据详情首先显示“哪个版本、哪个任务、哪次实验、发生了什么”和与当前结论有关的片段，再提供原文、完整身份、分页和下载。关闭后回到触发位置。任务结果、保留决定、报告论据和失败原因都应能直接进入相应证据。

高级入口仍支持按类型与实验检索全部证据，保留稳定身份与字符偏移分页；不以字节数、文件路径或编号作为普通读者的主要阅读内容。渲染继续遵循纯文本与既有安全边界。

### 8.5 信息层级与小屏阅读

- 主要导航使用活动概览、版本对比、实验记录、研究报告；插件、运行详情、获取 Harness、设置仍可达。
- 同一页面只保留必要的概要，不重复顶栏、指标卡、表头和正文中的同一统计。
- 短中文任务名为主，正式标识可查；重要状态用文字加视觉标记，不能只用颜色。
- 折叠的是阅读细节，不是关键警告、计分条件或必需操作。按钮应说明对象，例如“查看 H1 的依据”。
- 在 1024、736、390 和 320 像素宽度审核。内容自然换行，主页面不得整体横向溢出；窄屏比较可以改为逐任务纵向卡片，不以缩小字体凑列。
- 所有主要交互可键盘操作，有可见焦点；手机点击区域足够大。主题变化后文字、边界与状态仍清楚。

## 10. 演示制作与批准流程

### 12.1 创建表单与资料冻结修正

额度设置按“时间与并发、可选上限、高级运行设置”分组。轮次与总实验次数放在一起，解释一轮可以包含多个实验，并显示当前任务数所需的 H0 最低实验次数。数值上限的模式选择与输入就近排列；右侧上下按钮必须完整位于输入框内，不继承普通按钮的最小高度。窄屏按单列显示，摘要同时列出时间、并发、轮次、次数和 token 阈值。保留原有小时/秒单位、空值与零值语义、软阈值及 Meta 规划规则。

创建失败不能统一提示用户“修改配置”：后台或网络错误保留输入并允许直接重试。同配置重试复用原创建请求，刷新后也保留请求身份；修改配置或成功创建后的再次创建使用新身份。

后台对每次新建重新读取生成的开发资料包，逐文档校验后原子归档，完成后才持久化活动。这样长时间运行的后台不依赖启动时缓存的资料身份。失败的冻结不留下新活动或半份资料包；已有活动和创建请求回放始终使用原身份，不将历史实验迁移到新资料包。浏览器验收须覆盖额度输入框的按钮边界、可选上限切换、手机宽度和实际创建；回归覆盖运行期间重建资料、半成品构建拒绝、旧资料不变及重复请求不重复创建。

### 12.2 实验进度、覆盖与历史快照

新旧工作台共用只读展示层，区分两个问题：实验执行到哪一步，以及统计是否有足够的任务覆盖。前者不能从成功率是否为空推断。

- 排队（reserved/queued）：尚未启动。根据当前活动和已记录计划说明暂停、等待计划、并发名额已满、收尾预留、token 容量或单次条件待确认；没有依据就显示“未记录进一步原因”。不预测启动时间。排队时长从本轮受理时间算起，缺失时不补零。
- 启动中、运行中：从 `startedAt` 展示已运行时长；完成后固定为 `finishedAt - startedAt`。结束时间缺失时不继续计时。
- 评分中：仅接受明确的实时阶段记录（`phase=verifier/grading/scoring` 或 `scoringStatus=running`）。当前控制后台尚未上报独立评分阶段，因此实际活动显示“运行中 · 阶段未细分”，可能包含执行、评分或归集。`scoringStatus=pending`、等待结果、运行时长和 Solver 截止时间均不能证明正在评分。补充实时阶段上报属于后续后台工作，本次不重启正在运行的后台。
- 覆盖不足：所选版本或统计范围中有任务尚无可计分结果，明确显示覆盖数与“暂不计算”。单任务区分未测、尚无结果、未计分故障、取消和待归因；不把覆盖不足当作实验仍在运行。官方空值保留，已结束尝试的完成分按绑定规则统计。
- 汇总中的尚无结果数量按该范围逐次记录拆为排队、启动、运行、评分或归集；只有总数而缺少逐次阶段的历史记录明确标“阶段未记录”，不借用当前活动填补。

报告和版本选择决定显著标记“历史快照”，分别使用报告冻结事实和决定时的尝试记录。运行期间报告的事实时刻按冻结的活动启动时间加已用时长还原，展示修订时间与事实时间分开；缺少原始时刻的旧整理修订明确标注缺失。历史运行时长以该快照时刻封顶，不使用浏览器当前时钟。历史表不提供终止实验或改名操作；原始分析文字、计分、证据与报告文件原样保留。

实施范围仅为两个 UI 插件、共享展示函数、文档及展示回归。更新浏览器资源即可生效，不重启控制服务，不改动运行计划、活动配置、运行进程或冻结执行包。验收需覆盖真实活动只读显示，以及隔离样例中的明确评分、并发等待、缺失时刻和历史状态不随当前进度漂移。

验证记录（2026-10-20）：80 项 JavaScript 单元检查（含 10 项状态/快照回归）、4 项工作台认证与插件生命周期契约、两个 UI 构建、依赖边界检查通过。实际宿主只读核验了经典与 Studio 的排队/运行分离、等待原因、缺失覆盖、旧报告修订和历史时长不随轮询增长；历史报告终止按钮为零。1120、390、320 像素布局检查无根容器横向溢出，浏览器无新增错误。控制后台进程未重启，活动持续运行，核验前后用户配置和资源计划相同。实际后台仍不提供独立评分信号；明确评分阶段的分支仅以隔离输入回归验证，不宣称实时阶段上报已完成。

### 14.2 默认矩阵与实验入口

基线、当前保留和最新候选默认显示，重复身份去重，未产生的候选不补造。允许加入或移除其他比较对象，显示完整任务集与筛选范围；不同或缺失条件仍可供参考，但就近提示限制，不给出无依据的提升量和排名。旧版默认排除不同条件候选的展示策略按此调整，计分和选择规则不变。

每格显示后台成功率及成功数/纳入分母，运行、排队与其他待定状态独立显示。无结果、未测试和失败有不同文案，不将无结果显示为 0%。点击单元格展开对应版本/任务的实验，点击版本可查看其全部实验；筛选和数量使用相同范围。逐次记录不能只按当前列表序号命名，应能回到准确轮次与实验。

实验列表可切换全部、运行/启动、排队、已结束等实际状态；报告尚未产生时显示待归档或未完成，不设置失效链接。故障简述与成功/失败同层，详细诊断后置；真实活动的终止入口保留，历史视图不提供终止。收起返回触发位置，证据关闭后仍保留原筛选和阅读上下文。

### 14.3 简短解释与缺失状态

简短结论读取后台持久解释，不能在前端用规则拼出不存在的开发理由，也不能仅对长正文做截断。插件未记录动机、选择未记录备选或历史证据不可用时就近说明，仍提供已有事实与原文。关键局限不藏到最深层。

历史决定显示当时时间和依据，最新矩阵显示当前事实时刻；报告修订时间与事实时间分开。后续补充的解释显示作者/来源及整理时间，不覆盖旧理由。前序活动的证据显示完整来源路径的业务含义和访问状态，不将历史成绩作为当前候选结果。

正在运行不等于正在测量或评分。未接入可靠阶段上报时沿用“运行中 · 阶段未细分”等真实表述。下一步研究计划与已受理实验分开；断线保留状态时间及陈旧提示，不继续模拟进度。

### 14.4 规模、操作保留与验收

参考演示中的三版本两任务只是样例。大量版本提供搜索/选择，实验与转折提供分页或按需展开；窄屏按任务纵向排列版本，不将所有内容压进极窄表格。长中文、无数据、加载失败和连接断开同样可读。

创建、启动、暂停、恢复、停止、额度、资源计划、供应商与模型、改名、冻结源码、报告修订/下载及独立项目导出均保留。阅读改版不自动提交控制操作，不修改候选身份、历史记录或预算。

正式验收覆盖概览→插件动机→证据、矩阵→实验→报告、当前选择→备选→历史依据三条路径；核对默认层可理解、深入后可验证、统计一致、缺失诚实、关闭返回与键盘可用，以及明暗主题和 390/320 像素无根容器横向溢出。参考布局允许调整，功能和语义不能以“演示已通过”替代真实接入检查。
