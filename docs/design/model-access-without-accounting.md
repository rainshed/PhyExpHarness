# 移除用量账本与消耗统计

2026-10-24 起，新活动采用 `modelAccessPolicy: control-only-v1`、`meta-tools-v8` 和 `meta-system-v10`。本方案取代此前针对新活动的 token 记账、统计和软预算要求。历史冻结活动仍遵守原契约。

## 当前行为

新活动不设置总 token 阈值、收尾 token 预留或参考插件 token 子额度，不预留、结算、追补或对账，不按未知用量阻止调用。Meta、Solver、参考模型和参考 Harness 使用相同边界。连接测试只核验模型响应、流式输出、工具调用与工具返回，不要求 usage 回执。

每次模型调用仍检查可信宿主的租约、调用者身份、活动状态、原有截止时间与存储容量。`/model-access/{lease}` 只读取运行权限，不写请求账本。Meta 主会话及研究子会话必须已注册。存储不足或控制服务暂时不可用可以等待，等待受取消与原截止约束；凭证、协议异常或停止拒绝不能放行模型。控制服务仍承担调度和权限职责，不承诺脱离后台运行。

保留活动与 Trial 的持久状态、幂等受理、轮次、实验次数、并发、benchmark 时限、墙钟、暂停恢复、停止与收尾、存储保护、官方评分、诊断和轨迹。输出上限、上下文容量及异常输出保护属于模型执行条件，继续生效。费用与 token 总量不再是平台停止条件。

Meta 计划仅分配并发和收尾时间；新活动每题求解与评分时限来自 benchmark。报告和版本比较使用任务表现、稳定性、耗时与实验次数，不提供累计或分项 token 成本。原始响应中的 usage 可以随轨迹归档，但不重新汇总为活动用量。API 用 `usage: {status: "not_collected"}` 表示未统计，不伪造零消耗；新报告与选择快照省略用量分项。

## 历史兼容与发布

后台根据已保存的活动策略选择协议，用户不能为新活动选择旧记账策略。旧活动、在途进程、冻结组合、评分和报告不热迁移、不清空。`/accounting`、旧预算适配器和账本读取仅服务旧活动；新活动调用这些记账接口会被拒绝。`meta-tools-v7` 的准确工具资产保存在独立协议目录，旧冻结契约仍可核验。

升级源码和重建工作台不会修改已经运行的进程。新行为从维护更新后的后台及新建活动、新冻结执行版本生效；旧活动完成后才能进一步评估兼容代码清理。不得通过修改冻结资产使旧活动伪装成新策略。

工作台取消统计与 token 配置入口。无待确认创建请求的旧草稿先备份，再清理旧 token 设置；创建结果未知的请求保留原参数和身份，以便幂等恢复。历史原始数据保留在原归档中。

独立导出的新执行项目不提供 token 总量限制，仅保留运行时限与固定模型条件。隐藏的旧 CLI 参数只供旧活动控制器兼容调用，不能给新独立运行重新启用 token 预算。

## 验证

离线检查覆盖：连续无 usage 的模型响应、无预留或结算请求、SQLite 写事务期间的只读调用检查、主会话与研究子会话身份、凭证/协议失败、存储等待、取消和截止、暂停恢复、次数与并发限制、重启不重复启动、新报告无用量统计、旧账本对账与旧工具摘要保持兼容。连接测试使用本地模拟服务，不进行真实模型或科学实验。
