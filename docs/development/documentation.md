# 文档维护规则

状态：持续适用。开发变更须核对并同步相关文档，将文档与实现一致作为任务完成条件。AGENTS 仅保留这一执行要求及本页入口，详细方法集中在本文维护。

完整目录维护在[docs/README](../README.md)，根 README 介绍项目和最短入口，AGENTS 保留开发规则与代码导航。

## 唯一职责与来源

| 变更或内容 | 核对与更新位置 |
|---|---|
| 目标、能力范围、产品约束 | product |
| 安装、配置、按钮、操作步骤和故障处理 | guides |
| 模块职责、数据流、接口机制与权限边界 | architecture |
| 冻结格式、默认协议与旧活动行为 | 对应架构页及 architecture/compatibility.md |
| 构建、测试、提交和维护方式 | development |
| 尚未完成的工作或已确认的实现差距 | plans；影响当前使用时同时在 guides 说明 |
| 被替代的设计、旧计划、旧运行说明 | archive |
| Meta 使用的工具、参数和开发方法 | knowledge/plugin-sdk 资料源，并重建资料包 |
| 字段、默认值、命令 | 对应 schema/源常量、package.json；相关说明链接到这些来源 |

一个规则只在一处完整解释，其余通过链接引用。文档描述代码实际状态；产品要求与实现存在差距时必须显式登记，不能为“对齐”删掉用户要求或把未实现能力写成已经可用。

## 每次开发的更新流程

1. **开始时确认影响。** 阅读相关当前文档和实现，确认本次改动会影响哪些规则、操作或限制。较大改动先在 plans 记录目标、状态与验收条件，现行指南继续描述实际可用行为。
2. **实现时同步正文。** 按上表更新受影响页面、示例和限制，相关代码与文档尽量在同一提交中完成。修复仅恢复原有约定、文档本身仍准确时，可以保留正文，并在交付说明中简述核对范围和无需修改的原因。
3. **验证关键声明。** 对照实现、配置和有意义的行为测试，核对默认值、操作前提、权限、失败处理及兼容范围。变更涉及的操作命令须实际验证；未具备条件的验证明确标注，不写成通过。
4. **完成后处理计划。** 最终行为进入指南和架构，已完成计划归档；剩余工作明确保留在 plans。更新相关实现核对条目，区分已实现功能、实现差距与验证缺口。
5. **提交与交付。** 按下文完成检查，交付说明包含文档更新范围和验证限制。文档同步不自动扩大本次任务的实现、实验或发布授权。

## 更新方式

功能变化时改写当前正文，移除失效描述。不要靠顶部“以后文为准”保留一整篇互相矛盾的操作规则，不不断追加日期增量让读者拼版本。

当前页面写清适用契约、操作前提和已知限制；数值字段优先链接 schema/常量。涉及历史支持时集中更新兼容页，不把仍在支持的行为只藏在归档。

开发尝试、命令输出、失败排查和现场记录保存在本地开发记录中。正式文档保留最终规则、使用限制和可复现验证方法，避免变成逐次开发日志。

计划列出目标、状态、未完成项和可验证完成条件。实现后将最终规则移入当前文档，计划归档；归档本身不等于所有验收通过。旧计划中的授权、执行者与阶段要求不自动适用于新任务。

## 迁移和归档

被替代的文档保留在 archive，并标明历史状态和现行入口；旧路径与新入口在[历史索引](../archive/README.md)对应。现行规范按职责维护，历史正文中的状态不作为当前承诺。

移动时更新相对链接、锚点、README、AGENTS、包说明和机器读取的 SDK 指南；代码/脚本内有实际路径依赖时一并调整。不保留多个含正文的“新旧现行副本”。SDK 生成器仍读取原资料源位置，现行 docs 不替代其生成入口。

归档保留历史正文及可解析的来源链接，可以修复旧错误链接，不能据当前状态改写过去验收结论。当前页面只能将 archive 索引用于历史导航，不能把归档设计作为当前操作前提。

## 检查与验收

运行 `npm run check:docs` 检查本地 Markdown 链接、目标标题锚点、当前页面可达性及归档引用边界；生成目录、本地记录和外部网址不作为该检查的语义验证对象。链接通过不表示内容正确。

功能声明需对应[实现核对表](implementation-audit.md)中的实现和有意义的测试，核对创建默认、数据来源、状态转换、权限、兼容与错误路径。行为检查按[验证说明](testing.md)选择；仅修改文档维护规则时，检查内容、链接和项目边界即可，不因此重跑无关业务测试或真实模型实验。改动 SDK 资料源后还要运行 `npm run build:knowledge` 并验证生成包内容。

验证结论注明日期、源码基线、实际命令与覆盖范围，区分通过、失败、跳过和未执行。核对表的当前功能映射随实现更新，既有验证结果仍保留原版本归属；不能只改日期或测试数量，把旧结论自动继承为新版本已通过。复用已有证据时说明适用范围，存在新变更、失败或证据缺口才补充相关检查。

提交前检查没有将本地记录、密钥、现场配置或生成目录纳入 Git，再运行 `npm run check:project`。
