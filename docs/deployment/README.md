## 维护方式

通用功能与修复先进入 `main`，再同步到本分支。机器专属实现、脚本、配置与测试只在本分支维护，不把本分支整体合回主线。主线通用文档仍用于理解项目，部署操作以本目录为入口。

`npm test` 在此分支执行通用依赖检查和全部单元检查；`npm run check:deployment` 额外明确运行容器兼容与归档单元检查。`npm run check:project` 是主线专属的排除检查，在包含部署实现的分支应当报告违规，不用于本分支验收。实际单 UID 容器兼容性和 NFS 挂载行为仍须在目标环境使用部署 smoke 入口验证；本地模拟检查不能代替现场验收。

## 数据与切换责任

本次只建立 Git 分支，未更新现有实例。不要将新的标准主线直接指向已迁出证据正文的数据目录。需要迁回标准版本时，在部署侧停止归档回收、等待归档工作结束，使用本分支的恢复工具恢复全部正文及路径，核验摘要与可读性，再独立安排版本切换；原冻结的单 UID 镜像与活动仍需匹配的运行时。仅禁用归档开关不会恢复已迁出的内容。

完整回退依赖控制数据库、报告与证据正文、归档索引/策略以及冻结资产的对应版本。维护备份保存在受管数据目录之外，混合活动备份的保留与删除由运维负责。历史资料不授予新的远程操作、活动删除或模型试验权限。
