# NFS 主存储布局与更新

适用：部署分支中的 `nfs-primary-v1` 布局。此布局通过 `PHYEXP_DEPLOYMENT_PROFILE` 显式启用，不改变未配置实例的路径行为。容器仍使用[单 UID Podman 策略](runtime.md)。

## 来源与配置

部署实现来自原基线 `fd0465b` 上的三组现场补丁：`0001-nfs-primary-v1.patch`、`0002-bulk-metadata-views.patch` 和 `0003-sharded-report-facts.patch`。导入时核对原发布包 `20261026-nfs-primary-v3` 的全部 590 个文件与运行目录一致，源码包 SHA-256 为 `f6693b4d75473993c8d3068a39224a18a5c3e8a482cadbb2bf5f6e9329dac3d4`。部署分支保留之后的归档跨活动引用修复；历史现场日志、个人配置、凭据和实际数据仍在仓库外。

配置文件使用绝对物理目录，示例如下；路径须按目标实例替换：

```json
{
  "version": "nfs-primary-v1",
  "persistentRoot": "/persistent/phyexp/instance",
  "stateRoot": "/local/phyexp/state",
  "cacheRoot": "/local/phyexp/cache",
  "scratchRoot": "/local/phyexp/scratch",
  "containerRoot": "/local/phyexp/containers",
  "cacheMaxBytes": 4294967296
}
```

`PHYEXP_DATA_DIR` 指向同一 `persistentRoot`。后台与工作台保留一致的数据、UI home、控制 URL 和部署配置；发布时沿用实例的服务环境，不用标准首次安装命令替换现有托管服务。

## 存储与读取行为

- 活跃控制数据库、提供方设置数据库、归档索引和文件锁位于本地 `stateRoot`；报告、证据及冻结产物仍以持久根定位。
- 独立插件库的索引、补录进度及发布日志使用同一控制数据库，插件源码与 H0 模板保存在持久根的内容对象中，发布与清理复用本地对象锁。创建活动同时固定用户 H0 和部署布局；同步新版本不改写旧活动起点，也不自动导入全部历史插件。
- 新 Trial 的 main 输出、qsim 公共结果及私有日志直接绑定到相互隔离的持久目录。main 只读访问公共结果，不能访问 qsim 私有目录。已有冻结运行不自动升级。
- 已关闭正文和构建产物在同一文件系统内尽量共享 inode，保留完整摘要校验。生产者写入期间不共享正文；容器成功部署后清理临时构建 tar。
- 本地可信执行缓存受 `cacheMaxBytes` 约束；容量准入分别检查本地和持久位置。探测超时暂停新生产者，不能把未知空间当作健康活动必须终止的证据。
- 报告事实保留原始不可变快照和身份。大型事实视图使用完整元数据分片，正文通过既有校验入口按需读取；不删除报告字段或改变官方评分。

## 同布局发布与回退

1. 将新主线合入部署分支，核对部署补丁的重叠代码、依赖锁、SDK 资料和冻结执行资产清单。通过文档、通用依赖、单元和部署专项检查。
2. 在新发布目录安装依赖并构建。隔离测试数据使用独立本地状态目录和 NFS 持久目录，不能让验收后台打开正式数据库。
3. 切换前确认 Trial、Meta、参考运行、构建、归集、归档和删除工作均无在途进程。保留旧服务定义、环境文件和旧发布目录。
4. 退出正式后台和工作台后，备份完整持久数据、本地状态、归档策略/索引及受保护配置到实例目录之外。保留硬链接关系；核对数据库完整性及关键文件摘要。冻结镜像保留原身份，不执行无差别清理。
5. 服务指向新发布目录，沿用同一布局与端口，先启动后台再启动工作台。检查健康、登录、历史活动、报告、证据及容器隔离。
6. 回退仅使用兼容同一布局的旧发布。若新代码改变数据库或文件格式，先退出进程并按对应备份恢复，不让旧代码直接打开不兼容数据。

更新既有实例不自动创建活动、不重跑评分、不修改模型或旧活动冻结配置。新功能通过新活动冻结版本生效。

## 检查与限制

`npm run check:deployment` 覆盖容器适配、归档、分离状态目录、挂载边界和报告事实完整性；`npm test` 运行全部单元检查。真实 NFS 和 Podman 仍需独立无模型短流程验证。

历史详细索引自动淘汰和有界查询缓存尚未实现，本地 SQLite 不能承诺长期固定大小。真实 NFS 中断、目标并发峰值及空白宿主恢复没有因同步源码而自动完成验收。hard 挂载下应用超时不等于内核 I/O 已取消；持续阻塞仍需现场处理。
