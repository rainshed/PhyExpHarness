## 1. 本期交付与排除项

交付一条完整使用路径：用户在独立插件库中检索、阅读、管理历史插件版本，选择准确版本及配置，由平台检查并冻结 H0；活动中的 Meta 只获得选定内容及本活动后续成果，继续自主开发和实验。

本期必须完成：

- 独立插件库、历史冻结资产补录、新成果自动入库、用户删除和引用保护。
- 基础运行模板与插件装配契约；现有 Solver 请求与响应恢复作为普通可选插件。
- 用户选择插件、配置、依赖核对、组合检查、H0 冻结与来源展示。
- 后台、公共客户端、桥、Studio 和活动内 Meta 材料的完整接入。
- 旧活动兼容、准确导出、自动验证、人工验收材料和现行文档同步。

本期不实现 Meta 搜索全库、推荐或自主选择 H0，不提供相应工具或开关。未来可增加独立的 Meta 插件，但其读取权限与选择起点权限须由用户分别授予。本期不建设远程插件市场、完整组合市场、自动效果排名或新的运行框架；不修改已完成的晚启动与活动截止规则，不开展部署专属迁移。

库是本地运行数据，不是源码仓库目录。用户实验生成的插件、真实活动证据和库数据库不提交 Git；平台维护的恢复插件、装配代码、schema 与合成夹具可以作为项目源码提交。

## 3. 必须落实的设计契约

下列字段是语义要求，具体名称和数据库结构由 Agent 根据现有实现确定并进入 schema 或源常量；不把本文示例当作已经存在的 API。复用现有内容对象和原生插件加载机制，避免维护两套表示相同配置的权威清单。

### 3.1 身份、组合与来源

| 记录 | 必须确定的内容 | 身份规则 |
|---|---|---|
| 插件内容版本 | 源码及文件模式、入口、必要资产、配置规范、依赖声明与适用接口 | 同名同版本号而内容不同必须区分；外部标签或展示说明不覆盖冻结源码 |
| 库条目 | 内容引用、展示元数据、来源、派生关系、可选状态及删除状态 | 可管理的索引记录与不可变内容分离；同一内容可有多个来源 |
| Harness 组合 | 基础模板准确身份、插件内容版本、有效配置、装配关系、完整工程来源和依赖锁 | 改配置形成新组合，未改源码的插件继续复用；不纳入活动编号、时间或历史成绩 |
| 活动候选与执行包 | 组合引用、当前 Solver/外部条件绑定、准确构建产物、适配及回执 | 保留现有执行包身份语义；同组合在另一执行环境下不必得到同一 bundleId |
| 活动起点 | 明确的 H0 候选引用、用户选择快照、组合身份、来源及选择时间 | H0 是活动角色；新活动引用历史内容不宣称产生新实现 |

完整工程仍是正式候选与导出的依据。组合身份须覆盖实际影响实现的源码、配置及构建声明，不能仅哈希插件名称；构建产物和执行条件另有准确身份。相同源码重新构建得到不同产物时保留差异，不冒充同一已测产物。

### 3.2 保存、补录与删除

- 新源码在明确保存/冻结时形成快照，不为每次工作区编辑保存版本。构建前先持久保存源码快照，使构建失败也可留下可读取的开发成果；未通过检查的快照不能作为可执行候选或 H0。
- 成功冻结的插件自动登记，失败、未采用和被替换的版本不按成绩清除。检查失败、尚未运行和实际效果分别记录。
- 历史补录覆盖可验证的旧格式和当前完整工程，核验冻结摘要、源码位置、配置与依赖。缺失/损坏、无法定位或依赖原工程的条目返回明确状态，不能猜测拆分、替换源码或标为可直接组合。
- 补录任务保存进度和结果，支持重复执行与中断恢复。相同内容只存一份，但不丢来源；不重写旧候选、成绩、报告、编号、运行资产或开放活动状态。
- 用户可删除一个版本或整个插件条目。操作后从可选库中移除；依赖它的其他库组合或活动仍保留自己的冻结引用。新建组合不能继续通过已删除条目新增选择；已有活动可继续读取、运行和导出其资产。
- 删除前展示范围、引用数量和可释放空间的估计或“待核算”，明确保留哪些历史内容。库删除不等于删除活动历史，也不承诺所有字节立即释放。
- 删除记录持久保存，普通重扫、重启或重复自动登记不能复活已删除条目；用户明确重新导入才恢复可选状态。新内容版本是否可见按独立身份处理，不通过改名绕过同一内容的删除记录。
- 平台提供的恢复插件也遵守删除规则。初始化不能反复恢复用户已删版本；推荐预设引用失效时提示调整选择或显式重新导入，基础模板仍可单独使用。
- 库引用必须是独立的保留依据，不依赖来源活动存在。删除来源活动后仍能读取/装配入库源码；来源详情或原始证据不可用时如实说明。仅用于追溯的来源标识不等同于已授权纳入研究证据的强引用，后者保留既有删除约束。
- 内容发布、引用登记、目录删除和清理要处理并发与崩溃窗口。大文件处理在数据库写事务外，受管锁与持久任务保护未完成发布；冻结成功不能静默丢失库登记或保留引用。无引用内容才能按现有清理约定释放。

### 3.3 装配与 H0

用户流程为：选择插件版本 → 配置参数 → 核对完整依赖与冲突 → 检查组合 → 冻结 H0 → 启动。预览或检查后修改配置，必须重新核对新组合；不能把旧检查回执套到新内容。

- 基础运行模板也有准确版本并在 UI 可见；允许不选任何可选插件，检查最小工程仍能运行。
- 装配声明涵盖入口、源码/必要资产、框架或服务依赖、配置规范及有意义的加载关系。采用现有框架原生加载和依赖解析，不另造通用运行时。
- 首版一键装配支持当前基础模板下可验证兼容的插件；其他工程资产仍可保存/阅读，显示需要适配。不得把旧插件 schema 的能力白名单重新变成完整工程的策略准入限制。
- 传递插件依赖在最终清单中明确列出，随用户确认一并纳入；不静默补入未确认插件、不静默升级依赖、不自动改写冲突源码。第三方依赖遵循准确锁与现有隔离构建规则。
- 创建请求绑定准确选择、配置、依赖闭包与基础模板。更新、删除或重试发生在选择与创建之间时，按事务结果明确失败或重放已保存的快照；不能重新解析 latest，也不能另建一份活动。
- 后台显式保存 H0 引用，核对准备、启动、报告、比较、源码阅读和恢复路径中的首候选/空插件假设。H0 冻结后不能被库更新或当前工作区修改影响；后续变更生成新候选。
- 准备阶段不调用真实模型、不开始活动计时、不消耗 Trial；不加入 Meta 选起点的准备状态。移除新 process 创建表单的全套 H0 次数校验，保留其他合法性和历史未知请求回放。
- 页面分开呈现组合身份、活动编号、来源和本活动验证状态。历史成绩不进入当前统计；无本活动实验时显示“本活动尚未验证”。不强制测试 H0 或固定重复次数。

### 3.4 恢复插件与默认行为

首版将 Solver 请求与响应恢复作为一个平台提供的普通插件版本，内部保留现有策略配置，不要求拆成多个用户必须单独选择的小插件。

- 使用与其他插件相同的库记录、配置、装配与加载路径；迁移默认入口里的 recovery 专用装配分支。
- 收齐流检查、恢复协调、策略及其他必要源码；运行或导出时不从未声明的宿主目录取代码。
- 运行时截止从现有执行上下文传递，不写入跨活动插件内容身份，且不能提高用户上限。后台重启恢复、结果归集与隔离监督仍属于平台职责。
- 新活动可使用显式列出恢复插件的推荐预设；推荐预设保持当前默认恢复体验，用户可取消勾选。最小模板本身不隐含加载该插件；预设不是强制依赖。
- Agent 核对原生 profile、重试监听和供应商配置，说明关闭后剩余的基础协议行为；同一失败不能被隐藏恢复路径重复重试。用模拟故障证明启用/禁用的行为差异，不能仅断言配置字段已删除。
- 历史冻结配方与模板保持原行为。新读取/装配契约显式版本化，不直接修改旧冻结对象；导出包含所选恢复插件的准确内容。

### 3.5 活动内 Meta 的可见范围

本期库管理 API 仅供用户入口。Meta 主会话及研究子会话获得 H0 的已确认插件/依赖、基础模板、当前任务材料和本活动后续开发成果，不获得全库搜索、枚举、任意内容读取、删除或替用户重选 H0 的能力。

- 后台在活动创建时登记材料授权；仅提供选定资产的只读视图与活动内可编辑副本，不挂载整个库或其他活动目录。
- API、分页文件、源码读取、搜索、差异比较、证据路径和导出均核对活动归属与权限。猜中内容摘要、条目 ID、相对路径或先前回执不能绕过限制；未授权请求不泄露资产是否存在或其他活动元数据。
- 默认提示、SDK 示例、生成上下文、工具回执与构建日志不得夹带未选库插件的源码或历史报告。允许通用接口文档和正常框架依赖，不把用户要求扩大为禁止 Meta 学习或编写新代码。
- Meta 可以修改、移除已选插件，开发新插件、调整框架并形成后续候选。此自由不授予访问用户未选历史库内容的权限。
- 新成果入库由后台完成，给 Meta 的回执只包含本次操作和本活动内容。重复内容命中也不返回其他活动的来源列表。
- 用户选择插件只授权复用代码、配置及必要说明，不自动纳入来源活动报告、成绩或轨迹；历史材料仍按已有显式纳入机制处理。

## 4. Agent 工作包与完成条件

按顺序交付；访问控制从第一包开始实施，不能先暴露全库再等最后一包收紧。每包完成相关验证后立即本地提交，标题遵循仓库规范。最终 UI 入口必须齐全，不能只交付内部 API 或静态页面。

| 工作包 | Agent 必须完成 | 完成证据 | 当前状态 |
|---|---|---|---|
| P1 独立资产库 | 内容/索引/来源/引用契约，历史补录与新快照自动登记，用户查询/读取/删除，删除记录与并发恢复 | A01–A04；可重试补录入口及合成夹具；数据库升级前后核对 | 后台已实现，专项通过，完整集成验收待补 |
| P2 装配与恢复插件 | 基础模板版本、装配解析、配置/依赖检查、恢复插件打包与普通加载、准确构建及导出 | A05–A07、A11；无恢复/有恢复的实际加载和模拟故障证据 | 待实施 |
| P3 用户组合 H0 | 创建选择快照、显式 H0 引用、幂等/删除竞争、表单校验修复、客户端/桥/Studio 创建与来源展示 | A08–A09、A12；用户选择到准备完成的完整路径 | 待实施 |
| P4 完整入口与权限验收 | 独立库页面、版本/源码/配置/删除交互、Meta 材料过滤及拒绝路径、后台自动沉淀、文档和演示环境 | A10–A13；全部自动验收报告及 H01–H05 人工验收包 | 待实施 |

P1 提供用户管理能力和合成入口，P4 完成独立页面及整体验收；P3 的选择页面先复用同一查询与命令。不要在 UI、后台、Meta 工具内各写一套装配、计分或权限判断。

每包交付记录包含：实现与提交、受影响契约、自动检查结果、实际覆盖、失败及修复、剩余工作。索引异步完成时，页面应显示处理中或失败；不能把“源码已保存”误报为全部步骤成功。

## 5. 自动验收：由 Agent 编写、执行并修复

以下是行为验收要求，测试文件名由实际实现确定。复用现有测试入口并增加必要行为检查，不把与实现同构的字段断言作为唯一证据。

| 编号 | 场景 | 必须核验的结果 |
|---|---|---|
| A01 内容身份 | 同名同号异内容、同内容多来源、改配置、改源码 | 异内容不合并，重复内容不复制，来源不丢；配置只改变组合，代码改变插件版本 |
| A02 补录与失败源码 | 旧 v1/v2、完整工程 v3、缺文件、路径不明、依赖不完整、构建失败；中断后重扫 | 可恢复内容准确入库，异常逐项报告；失败快照可读但不可执行；历史对象和成绩未变，无重复条目 |
| A03 删除与保留 | 删除库版本/整条目及平台恢复插件、删除来源活动、共享依赖、重启重扫、显式重导入 | 新选择不含已删条目，已有活动仍可读/执行/导出；引用存续内容不丢；初始化不自动复活条目，失效预设有明确提示 |
| A04 事务与恢复 | 发布中崩溃、冻结成功但索引中断、并发删除/入库/清理、重复请求 | 持久引用完整，任务可恢复，未知响应按原键核对，不重复建活动/条目，不释放使用中的资产 |
| A05 装配合法性 | 空可选列表、兼容组合、传递依赖、配置无效、依赖缺失/循环/冲突、源码路径逃逸 | 最小工程可运行；真实加载与确认清单一致；无效选择有明确原因，未选插件不被暗中加载 |
| A06 恢复启用与关闭 | 相同故障序列下分别加载/不加载恢复插件，包括响应异常和工具参数故障 | 启用时出现预期恢复及记录；禁用时无该恢复链；无隐藏重复重试；普通成功请求保持正常 |
| A07 截止与取消 | 恢复等待遇到截止/用户停止；短窗口实验；有界 drain | 保持已有时间语义和真实中断原因，不延期、不无限等待、不把平台恢复变为候选策略 |
| A08 H0 创建与冻结 | 选非空插件、库升级/删除、检查后改配置、请求丢失、默认预设、旧草稿 | 明确 H0 引用；准确快照和检查绑定；幂等回放不重新解析选择；原活动不随库变化 |
| A09 统计与比较 | 多任务但 maxTrials=1、H0 未测、同组合跨活动、历史参考成绩 | 表单与后台一致；不强制基线实验；本活动未测如实显示；历史成绩不入分母，不伪造新实现 |
| A10 Meta 边界 | 主/子会话搜索、猜 ID/摘要、路径与分页读取、重复内容回执、默认上下文及材料挂载 | 可以读/改选定与本活动成果，不能枚举或读取未选资产、来源历史与库管理接口；后台仍自动保存新成果 |
| A11 独立导出 | 导出已选普通/恢复插件，库条目或来源活动删除后再导出，在独立目录检查加载 | 精确源码/配置/依赖仍可用，不依赖库数据库或原工程目录，不带未选插件和历史材料；静态/搬迁/真实运行分层记录 |
| A12 UI 与请求生命周期 | 浏览器刷新/切换、长版本列表、迟到响应、未知写结果、删除提示、配置错误 | 无重复创建或错误覆盖，能完成完整操作；删除影响和不可选原因可理解，无需手工改数据库 |
| A13 历史兼容 | 旧候选/配方/Meta 工具与模板、旧报告/导出、开放活动 | 旧身份和绑定不变，新策略仅适用于新契约；不因升级重新执行或迁移开放活动 |

### 执行与证据层次

- **单元与后台集成**：覆盖身份、引用、竞态、幂等、权限与统计，使用临时数据。已有[候选检查](../../tests/unit/process_candidates_test.py)、[插件读取](../../tests/unit/project_plugin_reading_test.py)、[删除检查](../../tests/unit/campaign_deletion_test.py)等可扩展。
- **原生与隔离执行**：用真实加载器、隔离构建及模拟 provider 验证组合与恢复；用实际受控接口和受限材料视图核验 Meta 边界。普通函数拒绝测试不足以证明运行时挂载正确。参考[process 策略契约](../../tests/contracts/process-strategies.test.mjs)和[恢复契约](../../tests/contracts/recovery-composition.test.mjs)。
- **浏览器与导出**：Agent 实际操作合成环境，完成选库、配置、创建、删除与页面阅读；实际检查[独立导出](../../tests/contracts/process-standalone.py)的来源与加载。结构测试不替代浏览器交互，换工作目录不等于 OS 层隔离。
- **真实模型与人工接受**：真实模型调用、科学评分、效果提升和人类接受单独记录。实现可先用模拟 provider 验证工程路径；真实服务验证按已有授权执行，缺少必要输入时只询问具体缺项，不把离线结果写成真实成功。

按[验证说明](../development/testing.md)执行相关专项；集成完成后执行现有 `npm test`、`npm run build`，并确保使用项目 Python 环境。涉及 SDK/Meta 契约或 UI 的更改分别完成资料和 UI 构建。新增检查入口进入 package.json 或测试说明，不在文档中虚构未实现命令。

每次提交前运行 `npm run check:project`，文档改动运行 `npm run check:docs`。环境不足时记录具体未执行项及影响，继续完成不依赖它的工作，不声称该层已经通过，也不把技术排错转交人类验收。

## 6. 人类验收：Agent 准备，用户确认

人类验收重点是产品操作和信息表达是否符合意图。Agent 负责技术验证、准备可运行的临时实例、合成示例、准确页面入口和可重复操作步骤；不得要求用户自行排查构建、整理数据或手工执行故障注入。使用合成数据演示删除，不需要用户拿真实活动试删。

技术实现和自动验证通过后，Agent 一次性提交以下验收场景；等待人类意见期间可继续其他已授权工作。人类未回复保持“待验收”，不能由 Agent 代签，也不必为每个中间代码改动暂停请求批准。

| 编号 | Agent 预先准备 | 用户实际检查 | 通过条件 |
|---|---|---|---|
| H01 找到并读懂插件 | 至少两个来源活动、同名不同版本、失败/未采用版本、缺说明样例 | 搜索插件，查看用途、源码、版本、来源和状态 | 能分清内容版本与来源；不把已保存/能构建/运行过误认为已证明有效 |
| H02 组合 H0 | 普通插件、恢复插件、依赖提示、一个不兼容示例及最小模板 | 选择准确版本、改配置、核对依赖，分别创建含恢复和不含恢复的 H0 | 能完成创建，知道实际加载内容；不兼容原因和恢复开关含义清楚 |
| H03 理解活动起点 | 已冻结 H0、历史相同组合及当前尚未运行的活动 | 查看 H0、来源与验证状态；查看旧活动参考信息 | 能理解“内容复用但本活动尚未验证”；不会把 H0 当作强制完成的基线成绩 |
| H04 删除与保留 | 被历史活动引用的合成插件、无引用版本、删除预览和重扫回执 | 删除版本或整条目，查看库及历史活动；核对空间提示 | 理解库中移除与历史保留的区别；新建不可选、历史仍可读，重扫不复活 |
| H05 Meta 访问范围 | 选定材料清单、一次本活动派生示例、自动权限检查摘要 | 核对活动只提供选定插件及依赖，新成果回到用户库 | 范围与用户选择一致；界面没有 Meta 选库入口；不会将技术拒绝测试伪装成人工安全证明 |

验收记录包含提交标识、演示环境、场景编号、Agent 提供的证据、验收人及日期、通过/需调整/待验收、具体意见。记录留本地开发报告；正式文档只维护规则、可复现步骤及仍存限制。涉及用户意见的修改由 Agent 完成并补充相关回归，再交付受影响场景。

交付须分开报告以下状态：

| 层次 | 完成条件 | 初始状态 |
|---|---|---|
| 实现 | P1–P4 的端到端路径、兼容和文档全部完成，本地提交可追溯 | 待实施 |
| 工程验收 | A01–A13 有对应证据，相关单元/集成/原生/构建/浏览器/导出检查实际通过，无未解释的失败 | 未执行 |
| 人类验收 | H01–H05 获得明确意见，需要调整项已处理或用户明确接受限制 | 待验收 |
| 真实模型验证 | 按授权的准确模型、任务与上限执行并记录；未执行不能声称已通过或效果提升 | 未执行，单独安排 |

真实模型验证不是本期实现与工程验收的隐含前置条件；未获授权时保持未执行并交付其余结果。本期不要求证明恢复或任意组合带来科学效果提升。

Agent 完成实现和工程验收后应交付可供用户直接验收的结果，不因人类尚未回复而停止其他必要实现，也不将人类待验收标成全部完成。最终回复列出提交、已实现路径、自动验证范围、尚缺层次及人类验收入口。全部本期完成条件满足后按文档规则归档；未完成的验证保留明确待办。
