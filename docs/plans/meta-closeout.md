# 通用主动收尾

状态：已确认方案，待实现。产品依据见[产品要求](../product/requirements.md)；当前旧实现仍采用 goal-or-budget-v1，主动收尾只接受 stable，并要求 stabilityRule。本文不表示新入口已经可用。

## 范围与行为

- 保留 campaign_finish，主 Meta 必须提交非空 reason（结束理由）与 summary（本次活动的实验总结），沿用写操作的 idempotencyKey。
- 总结指导说明做了什么、主要结果、结论、未解决问题与局限；不将这些建议拆成强制结构，不审批研究判断。
- 不要求 condition、候选、稳定性认证、成绩、实验次数、证据列表、每轮或最终分析报告。
- 原子保存理由、总结和结束决定，关闭新增实验并取消未启动项；已启动工作在原有截止和取消约定内结束并归集，随后结束活动。
- 理由和总结已保存后，报告缺失、未选版本、会话故障或缺少额外回复不触发新研究或无限等待。
- UI 与可读报告展示 Meta 的理由和总结，明确活动结束不是目标达成认证。非主动结束且没有 Meta 总结时明确缺失，系统事实摘要保持独立作者来源。
- 新策略、工具和提示词按新版本绑定；保留历史活动的冻结契约。既有实例转换、远端部署与可编程收尾插件不在本次范围。

## 实施顺序

1. 更新产品要求与本计划，保持现行指南准确标注旧实现。
2. 实现新契约、后台状态转换、通知/恢复与收尾逻辑。
3. 更新页面、可读报告、SDK 资料、当前架构、指南与兼容说明。
4. 完成相关行为测试、构建、项目及文档检查，将最终规则移入当前文档并归档本计划。

## 验收条件

- 自定义目标、没有 stabilityRule、没有候选或实验，也能凭理由与总结主动结束；不合格成绩及缺失分析报告不阻塞。
- 空理由或空总结被拒绝且不关闭活动；未授权子会话不能调用；重放不重复决定，不覆盖已提交总结。
- 在途实验、参考实验、构建与归集按原边界处理，未结束工作不被伪装为完成；无新增工作。
- 已提交理由与总结后，Meta 无额外回复或发生故障也能结束，不反复唤醒研究。
- 用户停止、截止和故障路径不等待永远无法取得的 Meta 总结，显示缺失而不伪造。
- 新旧工具与策略分别验证；历史冻结绑定不被修改。
- 文档、SDK、UI 与实现一致；不把离线检查声称为真实模型或远端部署验收。
