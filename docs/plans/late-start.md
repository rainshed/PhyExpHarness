# 实验晚启动与活动截止

状态：待实现。产品依据见[产品要求](../product/requirements.md#实验控制与计分)。本次只调整实验时间控制，不涉及 H0 选择、插件库、真实模型实验或实例切换。

## 目标与边界

新活动允许在剩余时间小于 benchmark 阶段上限之和时提交并启动。上限表示最多允许耗时，不是启动所需的最低预留；启动风险由 Meta 判断，历史预测不作为准入条件。并发、次数、暂停、容量及收尾预留约束继续有效。

默认硬截止终止剩余求解和评分，不自动延长预算。用户明确选择的 drain 模式仅允许截止前已启动的任务使用有限额外时间。结果归集和清理可完成已有证据持久化，不借此继续求解或补跑评分。

任务原始阶段上限保持不变，活动实际截止另存。活动截止、任务超时、人工停止与执行故障分别记录；可信官方结果保留，无官方结果按原计分规则处理，不伪造官方零分。

## 实施范围

1. 为新活动绑定版本化的晚启动策略；旧活动、冻结配方与历史报告不改写。
2. 打通调度、宿主预检查与 Solver 开始执行三个环节；排队到期不得启动，主线与参考实验使用一致规则。
3. 保存任务上限、实验启动及 Solver 开始时实际可用时间、准备/求解/评分实际耗时与中断原因。没有证据的耗时保持未知。
4. 更新 Meta 状态、系统提示、SDK 资料、UI 与比较说明。短窗口显示风险，完整窗口和短窗口不能静默混为同一条件。
5. 更新当前架构、指南、兼容说明和实现核对表；实现后将本计划归档，现行文档描述实际可用规则。

## 验收

- 剩余 30 分钟、任务上限 150 分钟时能启动；20 分钟完成可正常归集。
- 到期未完成准确记录活动截止；任务自身超时与人工停止可区分，先行故障不被取消覆盖。
- 排队到期、暂停、收尾预留、并发和次数限制仍有效；明确选择 drain 时仅在途工作可延期。
- 准备过程消耗时间后，Solver 仍可尝试；原 benchmark 上限不被改写。
- 时间条件可由 Meta/UI/报告读取；无数据不伪造实际耗时，历史策略仍能读取。
- 通过相关行为测试、SDK/UI 构建、文档与项目边界检查；真实 Docker/模型及浏览器人工验证单独说明范围。
