# 参考模型与参考 Harness 插件开发计划

日期：2026-10-23 · 状态：P0–P5 工程实现已落地，P6 工程验证通过；真实模型与效果评估另列 · 设计基线：[参考实验插件设计](../design/meta-reference-experiments.md)

用户已授权实施。两个可独立移除的插件、三种参考 Harness、UI 授权和 Meta 自主选择已实现；以下工作包保留原验收目标，实际完成范围见第 6 节，不把脚本 provider 验收记为真实模型实验。具体执行遵循[开发任务书](meta-harness-development.md)。

## 1. 交付目标与固定决定

1. `meta-model-reference`：参考模型来自 DeepSeek Harness 原生配置；用户可选多个，不绑定 Meta 模型，不维护重复目录。单独开启时运行当前冻结执行 Harness 的独立参考配置，不改写原候选或固定 Solver。
2. `meta-harness-reference`：默认使用活动固定 Solver，首期接通 Codex、Claude Code 和 DeepSeek Harness 标准模式。标准模式以锁定上游完整 `sdk` 组合为基线，不能用 H0 的 `sdk-minimal` 充当。
3. 两插件同时开启时允许参考模型 × 参考 Harness。UI 提供独立开关、多选目录、Meta 自主选择/用户指定配对、兼容矩阵；Meta 只能使用用户允许且经核验的组合，不自动穷举。
4. 两插件使用原生装配机制，各自拥有入口/契约/资料，不互相依赖。四种组合可运行；联合运行须两项能力同时有效，无第三个必需插件。关闭一项能力撤销相关新提交和排队任务，另一插件的单维参考及历史仍可用。
5. 原生模型绑定、Harness 配置、组合策略和实际条件准确冻结；所有参考运行共享活动限额、调度和监督。联合运行只记一笔支出，但同时遵守所涉及的插件子额度。增加适配器不改 Meta 工具形状和公共 UI 流程，不复制 Agent 循环、评分器或账本。
6. 模型参考、Harness 参考和联合参考与主线分组，轨迹、选择理由和研究解释可追溯。联合变化不单独归因，参考运行不能直接成为主线候选或满足固定 Solver 的稳定停止标准。

## 2. 实施前基线与修改位置

| 当前事实 | 实施工作 |
|---|---|
| 原生 Meta 已有作用域、业务工具、固定宿主和独立后台 | 在这些边界上增加两项可选能力，保留原恢复和角色规则 |
| 插件模块定位限于 `packages/meta-harness`，契约集中绑定 | 支持受信可选包的声明入口、契约、内容闭包、卸载及后台能力授权 |
| 项目供应商目录与 DeepSeek Harness 原生配置分别存在 | 增加可信原生配置发现/解析桥，参考模型以原生配置为权威，不双写目录 |
| 候选包含固定模型、现有 batch/trial 围绕候选组织 | 增加独立参考执行身份、批次和运行关联，保持原候选不变 |
| 监督、计量、通知、停止审查目前围绕主线工作 | 纳入参考在途工作、预算、取消、收集和恢复，不增加免费路径 |
| 材料、研究修订和报告支持准确来源 | 扩展参考来源类型和版本化报告投影，保留旧协议 |
| 当前执行 profile 使用 `sdk-minimal` | 单独核验标准 `sdk` 的能力、隔离与工具映射；不能据包已安装宣称接通 |
| Codex 公开提供非交互/SDK/app-server 入口 | 固定 Solver、环境、逐请求计量和中止仍需本项目工程验证 |
| Claude Code 公开提供非交互 CLI 和 Agent SDK 入口 | 验证原生模型绑定、MCP、隔离、辅助调用、禁用模型回退和进程/子会话中止，不能假设支持全部模型 |
| 当前工作台没有参考组合选择和联合参考记录 | 增加两维授权、兼容性服务、组合策略与矩阵，UI 和 Meta 共用后台事实 |

本表保留开工时的差异，不把旧设计中的目标段落视作当前能力。开工时复核 Git、正式文档和代码；本地记录可辅助，不能成为新克隆唯一的开发依据。

## 3. 分阶段工作包

### P0 原生配置与三种 Harness 接入验证

**产物：** 原生模型配置解析样例、三适配器能力报告、模型 × Harness 支持矩阵、环境映射说明、无真实模型的最小启动/工具/取消证据。

- 在锁定 dsh 中核验 provider/模型发现、调用默认值解析、profile 覆盖顺序和配置修订。准备脱敏快照、凭据引用与冻结 provider 恢复样例；验证原生配置修改仅影响新活动，工作台关闭后绑定仍可执行。
- 明确参考模型选择来自哪个受信 profile，桥仅对用户开放。使用两条合成 provider 路由验证同名模型不同路由不会混同；不读取或打印真实 key。
- 选择准确 Codex 版本，验证非交互事件、模型/推理设置、任务 MCP、进程树中止和用量。评估 CLI 是否足够；若改用 SDK/app-server，记录必要性及契约保持方式。
- 选择准确 Claude Code 版本，验证 `claude -p` 的事件、MCP 与权限配置、个人配置隔离、主/辅助请求、模型回退和中止；必要时评估官方 Agent SDK。依据原生绑定核验协议与有效设置，浮动别名和不等价映射拒绝；没有兼容固定 Solver 时不得暗换默认模型。
- 对 DeepSeek `sdk` 的解析配置和实际工具回执与 H0 比较，证明加载标准组合。核验原生文件/终端、任务工作区和 qsim 工具映射，不加载 Meta 业务工具或个人技能。
- 用脚本 provider 追踪包括压缩、重试和子代理在内的所有调用，验证没有绕过本次冻结模型/账本的隐藏通道。不能可靠请求准入或中止的接入保留不可用状态，先解决能力缺口。
- 定义兼容状态及证据门槛，区分不支持、未核验与暂不可用；至少准备一个支持配对、一个协议/设置不兼容配对及一个未核验配对。目录读取不调用真实模型，任意模型 × Harness 的互通不作为假定前提。

**退出条件：** 原生模型来源和三适配器的可执行边界有实际证据；不可兼容配置可在启动前被拒绝。脚本 provider 不冒充真实模型支持结论；外部依赖缺口明确记录，不要求运行真实科学任务或取得高分。

### P1 可选插件装配与版本契约

**产物：** 两独立插件包、可选入口/契约绑定、后台能力校验、参考策略/配置/记录 schema 与新旧兼容读取。

- 沿用 Cordis 和 Agent Preset，扩展当前受信包定位与内容冻结；只解析所选插件的入口/依赖。两个插件不加入完整 Meta 的必需列表，不以可选插件依赖抬高默认镜像要求。
- 将参考工具契约随各自插件版本绑定，禁止同名注册和错误版本混装；公共读取协议不反向依赖插件源码。保留既有工具/报告协议逐字节资产。
- 定义 `ReferenceExecutionSpec`、`ReferenceBatch`、`ReferenceRun`、适配器描述和脱敏原生模型绑定；增加 selectionMode、指定配对、requestMode、requiredCapabilities、兼容快照与实际比较差异。统一错误类别与有界回执；涉及报告的新引用发布新版本而非扩写旧 schema。
- 实现用户授权策略与实际组合校验，研究子代理、审查者和参考 Runner 不可提交参考实验；禁用后直接业务调用也失败。`reference_harness_submit` 仅在两项能力有效时接受 modelRef，不导入模型插件；取消联合工作按所需能力而非工具归属判断。

**退出条件：** 两插件开/关四组合可装配，包目录不可访问时无隐式导入；原有主线契约通过；新记录可离线读写并校验内容身份。

### P2 公共参考实验服务、预算与恢复

**产物：** 独立参考记录、共享账本与并发、监督和通知、幂等/取消/恢复、运行期能力停用。

- 复用现有任务准备、不可变镜像、单次监督、官方收集和内容对象。接受参考批次时在同一事务校验所有总限额和插件子额度，H0 最低覆盖与受理顺序不变。
- 按设计统一计轮、预留、启动计数、未知用量、等待、截止和收尾；单批只含一个配对。联合运行总账只计一次，同时检查两项插件子额度，三个互斥分组与插件重叠用量视图清楚区分。无分项额度不产生隐式固定比例。
- 纳入空闲判断、停止审查快照、最终报告事实和暂停/恢复；不能有参考任务仍在执行而活动已按主线空闲完成。
- 为启动/收集保存稳定身份与事件游标；响应丢失、后台崩溃和取消竞态不重复执行。无法核实启动结果时保留待核实状态，不盲目新起任务。
- 运行期停用立即撤销新受理能力，按 requiredCapabilities 取消排队（含联合），保留已开始工作的原租约或按用户选择中止；另一插件单维工作继续。权限修订在恢复后保持，用户重新启用不清零计数，不复活取消记录。

**退出条件：** 不调用真实模型的监督与故障测试覆盖准入竞争、恢复、中止和账本一致性；主线与参考共享限额可证明，假 adapter 仅作为测试夹具。

### P3 参考模型插件纵向闭环

**产物：** 原生模型选择 → 活动冻结 → 当前执行 Harness 参考配置 → 官方评分 → Meta 读取证据。

- 接通模型工具和原生配置桥，候选只读解析；每个模型/候选配对先做能力与装配检查，改变模型不改写源 Bundle。
- 使用全新任务/会话、原始公开输入和同一插件组合，原生 provider 语义经可信宿主与固定网关保留。配置不存在、原生配置不可冻结或不兼容时明确报错。
- 记录原生模型来源、provider 内容、有效设置和参考执行摘要；Meta 模型快捷选项也必须解析到有效原生绑定。
- 贯通脚本 provider 与真实任务验证器，证明收集官方零分也是有效结果；在已有授权覆盖的情况下追加最小真实模型运行。

**退出条件：** 另一参考插件未安装时本插件仍可独立完成闭环；源候选、主线成绩和固定 Solver 未改变，全部参考消耗计入总账。

### P4 参考 Harness 插件、三种适配器与联合参考

**产物：** 可选择的 Codex、Claude Code、DeepSeek 标准模式及支持矩阵；固定 Solver/已选参考模型的合法配对均经过同一任务评分、证据和取消接口。

- 先实现 Codex 适配，再接 Claude Code 和 DeepSeek 标准模式；P0 的最小启动样例扩展为真实隔离 Runner、工具桥、任务文件/提交和官方验证器路径。可按依赖可用性调整后两者顺序，不能省略其交付。
- 冻结所有配置和依赖，验证辅助模型请求、自动重试、模型路由、原始事件与未知用量。隔离开发宿主配置、其他活动文件与官方隐藏材料。
- 保留标准 Harness 原生能力，逐项列出受限环境的适配差异；缺失或重要能力被禁用时诚实标注，不用“标准模式”掩盖精简实现。
- 接通两插件同时开启时的 modelRef × harnessRef，统一记录一次执行、两项能力、准确模型与选择理由；分别验证独立模型参考、固定 Solver Harness 参考与联合参考。
- 使用临时第四适配器测试注册、配置发现、通用工具/UI 数据、故障和移除；不为此长期保留第四个产品功能。

**退出条件：** 三首期适配器在各自合法配对上贯通官方评分、全部消耗、取消与归档；两项能力联合校验有效，同名不同模型/路由拒绝静默映射。移除任一适配器不影响其他适配器、模型参考或主线；移除模型插件后 Harness 插件仍能使用兼容的固定 Solver。

### P5 研究关联、报告与 Studio

**产物：** 双开关、原生模型多选、三 Harness 多选、Meta 自主选择/指定配对、兼容矩阵、分组实验阅读、轨迹证据、研究到候选的来源链、停用操作。

- 公共客户端仅提供查询/命令和稳定类型；Studio 页面不导入可选插件私有源码。原生配置变更、活动冻结快照及凭据状态分别展示。
- 实现创建页完整流程：独立开关 → 选择允许集合 → 组合选择模式 → 兼容矩阵/列表 → 预算概览；保存不启动实验。两开关默认关闭，指定配对不可被自主选择绕过；新活动冻结策略，旧活动仅支持原能力停用/恢复。
- 运行页显示有效能力、允许范围、Meta 选择理由、在途状态和停用影响；手动提交仍检查同一策略/额度。禁用一项时显示受影响联合工作，不能把保留运行显示为已经停止。
- 主线矩阵保持原成绩口径；参考分组展示样本、官方结果、派生成败、成本、未知用量和条件差异。报告明确事实快照时间，历史时长不增长。
- 参考分为模型/Harness/联合三组；并排轨迹显示同模型/异模型/待核验与对照对象，联合结果不作单因果解释。四格对照缺项保持为空，不自动补跑，不把多个不同模型合成同一 Solver 比较。
- 接通研究记录/证据片段、候选采用理由与报告事实版本；一次参考成功不自动生成因果结论，不成为可保留候选。
- 检查四种开关组合、有历史无安装、仅一个 Harness 可用、所选模型无兼容配对、凭据失效、长轨迹、失败/待核实、取消和恢复等状态；阅读页面不调用模型，刷新不重发实验。

**退出条件：** 合成浏览器路径可完整使用，允许集合和两种选择模式的权限与 UI 一致，旧活动和旧报告不变；无插件构建和历史只读展示不需要安装 Codex 或 Claude Code。

### P6 集成验收与文档收尾

**产物：** 已实现入口与运行说明、准确支持矩阵、完整工程检查记录，以及授权范围内的真实模型/评分/研究闭环证据。

- 执行第 4 节矩阵，修复直接相关失败后再提交交付；每项检查写明 provider、版本、运行环境、范围和实际结果。
- 对真实模型调用核对已有授权和额度；不足时先准备可审阅的最小配置与次数计划，仅请求缺失条件，继续其他检查。本文档本身不授予真实调用权限。
- 实际调用集合覆盖至少一个原生配置参考模型、独立 Harness 参考、联合参考及三个 Harness 各自的已核验兼容配对。固定 Solver 不兼容某 Harness 时，使用用户批准的原生参考模型进行联合验收，明确其不是同 Solver 对照；不能为了凑齐三者暗换模型。每次使用新目录，保留科学失败和基础设施失败，无需大规模实验。
- 验证 Meta 在用户多选范围内读兼容矩阵、自主选择并提交明确配对，且不会越界、穷举或在指定配对模式外提交；至少一次运行展示选择理由和实际轨迹。真实不支持项保留，不因 UI 有选项而宣称已接通。
- 验证 Meta 能从参考轨迹形成带来源的观察，并提交一次后续主线验证；若要声称插件有收益，需另行开展足够的重复/独立任务实验，不在工程验收中补造效果结论。
- 更新运行说明、准确命令与已知限制；标记各阶段状态，仅依据已完成范围声明可用，不把本计划改写为一律已通过。

**退出条件：** 两插件可独立使用/移除、三个参考 Harness 在声明配对上可用、Meta 自主组合与 UI 授权一致、原生模型配置正确、预算/恢复/历史兼容均通过；真实外部依赖未完成时明确保留对应未验收项。

## 4. 必须覆盖的验收矩阵

| 范围 | 检查与预期 |
|---|---|
| 四种插件组合 | 无/模型/Harness/两者均能启动并完成原主线；可选源码移走后仍可构建和创建活动 |
| 真正关闭 | 工具、说明、监听与主动调用消失；直接后台请求也拒绝；另一插件不受影响，历史可读 |
| 联合授权 | 仅两插件都有效才接受 modelRef × harnessRef；伪造发起插件或直接调用不能绕过；没有第三个必需插件 |
| 自主组合 | Meta 只能从已选集合的兼容配对中选择；指定配对模式不越界；保存/刷新/加载不自动穷举或启动 |
| 兼容矩阵 | 支持/不支持/未核验/暂不可用有来源和原因；模型名相同、协议不同或设置不可表达时拒绝；创建校验不静默删选择 |
| 配置跟随与冻结 | 原生目录改变在新草稿可见，旧活动/创建幂等回放不变；同名异路由区分；未解析配置拒绝 |
| 凭据和环境 | 密钥及敏感 header 不进入快照/输出；执行环境看不到个人 home、Meta 工作区、隐藏评分数据和管理 socket |
| 源候选身份 | 参考模型替换只产生新参考配置；原 Bundle、配置、成绩、选择和导出摘要不变 |
| 干净任务 | 两参考运行不继承上下文、产物或测量状态；任务用途与反馈隔离生效 |
| Codex 固定模型 | 主调用、压缩、子代理和重试均按准确绑定计量；不兼容的模型/设置启动前拒绝 |
| Claude Code 接入 | 非交互/SDK、MCP、文件/工具/提交、评分和取消贯通；无个人配置、浮动别名、默认模型或回退绕过绑定；用量和事件有原件 |
| DeepSeek 标准模式 | 实际加载回执来自 base + sdk，区别 H0；原生文件/终端/qsim/提交完成，差异有记录 |
| 适配器扩展 | 临时第四适配器无需改 Meta 工具和公共 UI 流程即可接入；移除某适配器无残余依赖、未知项不回退 |
| 并发与额度 | 主线及三参考类型同时争用最后额度，不超额受理；联合只记一笔且同时检查两子额度，未知用量保留 |
| 次数/轮次 | 重放不重计；受理轮次不退、未启动预留可释放、启动失败占次数；H0 覆盖不能被参照挤占 |
| 截止与停止 | 排队不足、严格截止、有限收尾、用户暂停/停止、中止进程树均有实际监督；参考成功不能满足主线稳定停止 |
| 崩溃窗口 | 受理后响应丢失、启动后记录中断、收集重试、报告发布失败与重复通知都不重复任务/扣费或改原件 |
| 停用竞态 | 与提交/领取并发时事务裁决正确；关闭任一能力取消相关联合排队任务，另一单维工作继续；恢复不重开能力，重新启用不重置预算、不复活取消记录 |
| 证据完整性 | 超长输出、部分流、磁盘/收集失败可识别；摘要和片段可核对；公开事件缺项标未知 |
| 评分和统计 | 官方零分、空分、外部故障、人工取消依绑定规则处理；主线分母不混入参考，分组覆盖明确 |
| 比较归因 | 请求模式与实际身份差异分别保存；异模型 + 异 Harness 标联合变化，同名不同路由不冒充同模型；四格缺项不自动补跑 |
| 研究与报告 | 参考观察→研究修订→候选动机→主线验证可定位；旧分析修订不改写、加载页面不生成新模型分析 |
| UI 与恢复 | 草稿、过期响应、重复点击、离线重连、双开关、多选、组合模式/矩阵、手动提交、取消/恢复、窄屏及空白/错误状态可用 |
| 旧版与独立导出 | 旧活动不启用新功能；旧协议/Bundle/报告保持；Solver 导出无 Meta 参考插件、参考模型凭据或研究历史依赖 |
