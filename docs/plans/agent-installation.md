# Agent 安装与首次实验

状态：阶段 1–5 已实现，CI 工作流和本地启动契约已加入；本地干净源码验收及外部验证状态见下文。现行步骤见[Agent 安装流程](../guides/agent-installation.md)。

## 目标与范围

新人将仓库安装指南交给 Agent，提供本机必要路径、可用模型及认证后，Agent 能完成项目依赖安装、环境诊断、打开工作台和启动一次有明确上限的真实实验，并用后台事实核对结果。重复执行或中断后继续应复用已有安装与同一次活动。

主线只增加通用本地入口，保持标准 Docker/Harbor、本地数据、固定模型、隔离、官方评分和证据保存契约。既有研究活动默认值与独立导出包不因首次使用流程而改变。机器专属适配、服务托管、网络接入和实例发布仍由部署侧维护。

安装和诊断不调用真实模型。真实首次实验使用明确的 Solver、Meta、任务和运行上限；缺少凭据或条件时返回可操作的缺项，不切换模型或重复创建活动。工程测试与真实实验验收分别记录。

## 实施顺序

| 阶段 | 修改 | 完成条件 |
|---|---|---|
| 1. 依赖与配置 | 主项目独立 Python 完整锁；Node/Python 版本声明；后台/UI 统一数据目录；Harbor 获取及版本、镜像说明 | 快速开始只安装一组主项目 Python 锁；路径行为有跨平台检查；外部来源可追溯，未实测平台明确标记 |
| 2. 安装与诊断 | 不依赖项目已安装的命令入口，提供 setup、doctor；文本/JSON 结果和稳定退出状态 | 新环境安装、重复安装、缺依赖、错误 Harbor 路径、Docker 不可用均可区分；不覆盖个人配置或实验数据 |
| 3. 本地启动 | start、status，统一数据路径/端口，后台就绪后启动工作台；输出日志与登录入口 | 重复启动复用准确实例；未知端口占用明确失败；启动失败可定位；关闭命令不隐式停止实验 |
| 4. 活动命令 | 经现有用户 API 查询模型/任务、准备/启动/查询/等待首次活动；持久请求身份 | 请求超时及命令重启沿用原配置、活动与幂等键；复用认证与修订校验，不复制调度或评分规则 |
| 5. 首次实验 | 单任务、并发 1、有限实验次数的独立配置，校验 benchmark 时间及模型选择 | 准备与真实启动分开；结果区分完成评分、未评分、失败、仍运行；可定位工作台活动和证据 |
| 6. 验收与指南 | 干净源码环境检查、CI、Agent 安装指南、快速开始及架构/核对表同步 | 命令可照做；阶段成功条件与恢复步骤明确；离线、容器、浏览器与真实模型证据不混写 |

## 命令与失败契约

具体命令在实现时进入 package.json 与 --help；本计划不将尚未存在的命令描述为可执行。

- 配置优先级明确，数据目录、Harbor 路径、端口和模型配置可显式传入。已有环境变量契约保持兼容，不自动读取 .env。
- doctor 输出每项检查的标识、状态、原因和下一步。setup 使用固定依赖、项目虚拟环境和构建入口；系统软件安装/登录条件不足时列出用户需要完成的步骤。
- start 等待后台与 UI 就绪，记录可确认归属的实例信息与日志。命令中断或状态查询超时不等于活动取消，恢复前先读取事实。
- 首次活动保留配置、创建键、活动 ID 与启动请求身份，写入成功后才发送创建请求。结果未知先核对，不通过换键或新目录重试。
- 凭据沿用现有私有配置/环境/登录机制，诊断输出与回执不包含密钥或认证令牌。浏览器继续通过宿主会话访问后台。
- 首次验收要求真实 Trial 完成、官方评分产物可读取、证据已保存，并能在工作台查看。零分可表示工程链路完整，不表示科学效果；未评分与基础设施失败单独报告。

## 验证与交付

使用合成目录和假 API 验证重复执行、端口占用、启动超时、路径、请求身份、错误和终态。增加干净源码安装/构建/离线测试与临时数据服务启动检查，避免依赖开发者历史数据和相邻目录。

可用外部环境中的 Docker/Harbor、浏览器和真实模型验收另行记录准确版本、命令和结果。缺少外部资产、凭据或必要运行输入时保留明确待验项，不把模拟完成当作真实实验完成。

每个独立阶段通过相关检查后本地提交。实现后的现行规则进入 guides/architecture/development；计划完成后归档，未完成验证继续留在[待办索引](README.md)。

## 已完成与剩余验收

已提供独立主项目锁、路径一致性、setup/doctor、start/status/stop-local、模型与任务查询、持久首次实验 session、活动导航和完整操作指南。Ubuntu/macOS CI 配置覆盖离线安装和启动；本地临时源码副本已实际完成首次/重复安装、锁检查、真实后台/UI 桥启动与复用、首次计划生成和无活动退出。

尚未完成：GitHub 托管 runner 实际运行、其他平台/架构的完整容器准备、按指定模型与运行范围执行真实首次实验，以及浏览器人工验收。浏览器工具拒绝 file: 本地登录页，本轮仅完成 HTTP 认证与 UI 桥检查，不将其替代页面验收。这些验证缺口保留本计划，不标记为所有新机器已可用；准确检查结果进入实现核对表。
