# 模型请求恢复与任务失败计分修改计划

日期：2026-10-19。范围：执行请求恢复边界、任务最终结果、统一计分及插件开发资料。

## 1. 目标与边界

过载或连接中断只结束当前模型请求，不能永久封锁同一任务的后续合法请求。执行插件可以在 DeepSeek Harness 原生失败步骤接口选择恢复；默认不自动重试，也不自动重跑整个 Trial。Meta 继续自主设计恢复策略。

任务最终因模型服务过载、连接中断或响应连接不完整结束且没有官方评分时，派生任务完成分计 0，进入成功率分母；官方 null 保留。已恢复请求不作为任务终止原因。预算、截止、用户取消、固定模型和工具边界继续由外部宿主执行。

本次不开放网关源码给产品内 Meta，不改变 Quantum Harbor，不新增真实模型实验。其他未评分原因沿用现有规则；异常流保护仍终止不安全请求，不能执行截断工具参数。

## 2. 请求与任务状态

网关分别保存逐请求失败历史、必须停止的终止状态和最终任务诊断。过载、传输错误及无完整结束回执允许后续请求；其余现有保护终止规则保持。每次调用使用新的请求 ID，独立预留和结算；未知用量不能按零结算。全局取消后不再接受调用。

结构化错误包含安全的错误类别、网关请求 ID、可用的 HTTP 状态和 Retry-After。原始错误留在审计记录中，未知提供方错误不一概归类为过载。跨进程传输保持错误类别，使原生 agent/request-error 扩展点可供执行插件使用。

恢复重跑失败模型步骤，保留已完成工具结果。失败的部分输出保存在证据中，不进入下一次有效模型历史。通过相同会话和请求内容关联恢复记录，其他请求成功不清除尚未恢复的故障。最终诊断优先使用终止步骤的请求 ID，避免把最早错误冒充最终原因。

执行器、Meta 通道和诊断读取器同步采用新契约；历史归档继续按旧契约读取。已恢复故障显示为请求历史，最终任务成功时不挂载历史失败原因。

## 3. 统一计分

新增 task-completion-v2，新创建活动冻结此版本。缺少版本字段的旧活动继续使用 v1；历史评分、报告、选择快照不改写。

| 最终情况 | v2 派生任务完成分 | 官方评分 |
|---|---|---|
| 官方通过，包括恢复后通过 | 1 | 保留 1 |
| 官方未通过，包括恢复后未通过 | 0 | 保留原值 |
| 已结束，过载或连接故障导致无评分 | 0 | 保留 null |
| 正在运行或恢复 | 待定 | 保留原值 |
| 用户取消、环境或评分器故障、待归因 | 沿用原规则 | 保留原值 |

故障原因和计分结果分开：连接故障仍有外部原因，但在 v2 中其终止任务计 0。不能将笼统的 model_response_error 全部判为该类故障；以明确的规范化故障类别或受信诊断字段识别。

后台 outcomes 是唯一计算入口。工作台、报告、Meta 上下文、候选选择和停止审查读取同一活动版本。快照复用必须匹配规则版本。旧结果按新规则重算属于另行明确标注的统计投影，本次不自动迁移。

## 4. 实施顺序

1. 修改网关与进程桥：拆分失败状态，传递结构化错误，保持默认零次自动重试和固定宿主约束。
2. 修改执行器及故障诊断：保存请求恢复历史和最终失败，兼容旧文件，防止成功任务被历史错误污染。
3. 增加 v2、活动绑定和共享投影；同步契约、界面文案及 Meta 的规则说明。
4. 补充失败步骤插件资料和只读类型查询；以隔离环境中的测试插件验证真实原生恢复链路。
5. 完成相关离线测试、构建、边界检查，并在本地开发记录保存检查结果。

## 5. 验收

- 过载后可以发起第二次合法请求；默认无恢复插件时只调用一次。
- 输出中途断线后，测试插件重试成功；失败的部分参数不执行，之前的工具副作用不重复执行。
- 所有请求逐次记账，失败用量未知仍保留；预算拒绝、截止和用户取消不能被恢复插件绕过。
- 并发或不同会话的请求记录不互相清除；最终故障对应实际终止步骤。
- 恢复成功不被第一次失败污染；恢复耗尽的任务在 v2 计 0，v1 保持原口径。
- 官方评分优先于后续清理错误；待运行、取消、评分器失败等保持原语义。
- 工作台 API、报告、Meta 查询和选择快照的分子、分母、规则版本一致；原始记录不变。

新网关随新冻结 Bundle 生效。旧 Bundle 内容及基础设施摘要不变；后续效果对比应使用同一基础设施版本重新准备基线与候选。

## 6. 连接诊断补充

受信模型网关增加 `model-transport-v1` 诊断，覆盖 Node 原生 WebSocket/Undici 的请求与连接关联、复用、协议阶段、关闭及错误原因、SSE 回退。诊断从传输层观察适配器过滤前的事件；已安装的 Pi 适配器不透传 `start` 和完整诊断对象，因此不能只依赖其内容流判断连接阶段。脱敏审计保留错误原因，公开故障摘要只保留结构化事实。观测缺失保持未知，不改变执行策略。

计分延续 v2/v3：最终未恢复的连接失败为任务完成分 0，官方 `null` 保留；恢复成功采用最终官方结果。补齐 `WebSocket closed` 等明确传输错误的识别，避免正常携带关闭码的失败漏入泛化的 `model_response_error`。不重算旧活动。

验证覆盖响应开始前断开并回退、开始后无正文断开、显式恢复成功及恢复耗尽、关闭码、并发连接与复用关联、脱敏、官方空值保留和跨入口计分一致性。测试使用回环协议服务及虚构凭据，原始真实日志只留本地。
