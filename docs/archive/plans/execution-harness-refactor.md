# 执行 Harness 与 Quantum Harbor 链路重构计划

> 历史快照：来自 `docs/plans/execution-harness-refactor.md`，于文档重组时归档。正文保留当时的方案、状态和验收叙述，可能已被后续实现替代；不是当前操作指南，也不构成新的实施授权。现行入口：[当前说明](../../architecture/execution.md)；兼容行为见[兼容规则](../../architecture/compatibility.md)。归档不表示其中所有计划均已完成。

日期：2026-10-24。状态：P0–P6 已完成；完整工程、真实 Meta 闭环、官方评分及独立搬迁验收通过。第 9 节记录范围与证据。架构决策、链路审计及 R01–R37 限制清单见[职责设计](../design/execution-harness-boundary.md)。

## 1. 交付范围

将 Meta 的开发对象从“给固定 H0 追加插件”扩展为完整执行 Harness 组合。Meta 能修改候选的框架/profile、入口、依赖、工具、上下文与恢复策略；平台只执行用户和 benchmark 的外部约束、运行监督、官方评测接入和证据保存。

本计划必须交付：

- 同一套候选 check/freeze/test/query/export 流程，接受完整工程清单。
- 隔离构建与精确版本存储，支持候选声明的新依赖和实际构建脚本。
- 在 Harbor main 内运行的候选进程、受信最小 Agent 适配和 Trial 模型通道。
- 可替换的默认 DSH Harness，包含可选工具、上下文、压缩和恢复插件。
- 独立的执行状态、官方评分、证据完整性和比较条件，完整反馈给 Meta/UI。
- v1/v2 兼容、新 v3 基线、精确独立导出，以及自动和真实运行验收证据。

不把修改 Quantum Harbor 科学评分、改变用户 Solver、删除历史、恢复 token 预算或强制 Meta 采用某种研究算法纳入本次工作。用户后续已授权按本方案重构至完整验收；真实试验使用已授权的固定模型及独立活动，保留全部尝试。

## 2. 实施原则

1. 优先完成一个从候选源码到官方结果的完整小流程，再扩大策略能力；不先堆一套未运行的通用框架。
2. 新流程使用同一个运行契约。不得为重试、压缩、动态工具、子会话等分别增加平台特批接口。
3. 每个变更明确删除或迁移哪些旧约束。仅加一个 `allowX` 开关、扩大错误码集合、给 Meta 更多平台修复提示，不能算完成。
4. 文档、schema、实际运行与可导出内容保持一致；代码采用插件形式不等于 Meta 真能替换，必须由候选实验验证。
5. 构建、启动检查、合成故障、真实模型、官方评分和独立搬迁分别报告。没有证据就保留未完成状态。
6. 尊重工作区已有恢复增量，先核对其最终提交与测试。复用适合迁入候选的部分，不合并无关改动、不覆盖其他工作。

## 3. 阶段与依赖

阶段是实现工作包，不是逐项人工批准点。后续实施按实际授权连续完成可执行部分；本轮已获实施至验收授权。

### P0 固定现状与回归证据

**产物**：源码/运行依赖基线、限制处置表、代表性失败路径和新旧运行模式标识。

工作：

- 记录当前代码及在途恢复增量的最终身份，锁定 Harbor 包完整性、Quantum Harbor 检出和任务镜像；不能只记录版本号。
- 从 R01–R37 建立实现追踪，每项标记保留、迁移、删除及对应测试。
- 用合成代码重现普通 `RuntimeError` 与 Harbor Agent 非零退出对评分路径的差异，复现当前 collect 对已有分数的前置拒绝。
- 保留旧 v1/v2 运行、恢复、归档、比较和导出样例。真实故障日志只作为本地证据，不复制私人轨迹入库；可复用测试使用合成数据。
- 明确新条件将改变候选计算位置和资源口径，新基线不得复用旧分数冒充同条件运行。

**退出条件**：每项当前限制能定位到源码或实际环境约束；关键评分阻断有可运行的负例；历史兼容范围明确。

### P1 官方结果与执行状态解耦

**产物**：新结果契约、薄 Agent 的退出语义、可幂等重读的官方收集器。

工作：

- 建立执行/官方结果/证据/比较四个状态面；保留原始 rewards、report、exception、exit code、阶段和来源。
- 实际候选非零退出映射到 Harbor 原生 Agent 退出类型；超时遵循原生阶段计时。用户取消和环境故障单列，不能 catch 所有异常后伪装成功。
- 取消所有“无 exception、runtime completed、toolCalls≥1 才读分”的新链路条件。
- 允许已有官方分数与 Agent 错误并存；单个诊断附件缺失不阻止读取可信官方产物。
- 将结果修订从按 bug 名称补丁改为同一收集器的幂等重读；每次投影有版本与原始来源引用。
- 保留 v4 主指标，不自动排除平台失败、改分母或新增免费重跑。

**退出条件**：合成 Harbor 单步任务在候选非零退出、超时和正常退出时，按原生规则获得评分；有官方分数的结果不被平台内部状态清空。真正 verifier 故障仍如实无分。

### P2 完整候选与隔离构建

**产物**：`harness-composition-v3`、隔离构建器、候选产物缓存、通用 check/freeze。

工作：

- 定义源码、插件引用、framework/profile、依赖锁、build、entrypoint、runtimeConfig 与 runContract；使用现有内容寻址存储。
- check/freeze 接收工程清单，停止重写为平台 `h0-sol` 配方；保留旧参数的旧模式读取。
- 删除固定框架包、候选依赖/profile 与 H0 相同、2 MB 单文件、任务 ID 字符串拒绝、预装依赖和固定 capability 枚举等门槛；保留路径归属、包完整性和外部容量约束。
- 新依赖和构建脚本在无凭据构建环境运行，隔离工作目录、记录构建命令、锁和工具链。禁止在宿主加载生成代码获取声明。
- 构建结果按精确输入缓存，支持取消和明确日志；冻结引用已经验证的稳定快照，不重复相同构建。
- 平台契约检查不要求恰好一次模型调用、指定工具名称、全部工具装载或某个框架事件；候选策略单测与正式任务分开。

**退出条件**：两个候选可以使用不同锁文件和 profile，在同一外部实验条件下完成构建和冻结；源文件改动生成新身份，旧版本不变；构建脚本不能接触宿主/运行凭据。

### P3 main 内执行与最小模型通道

**产物**：候选进程启动链、只读运行上下文、可撤销模型通道，以及首个完整合成任务闭环。

工作：

- 由 Harbor setup 部署候选专属运行时与依赖目录，在 run 阶段启动候选入口；不修改任务/qsim/verifier 的依赖环境。
- 构建可移植 Node/Python 运行产物或声明并验证已有运行时，不假定 task main 预装候选所需语言版本。
- 提供任务原文、工作区、MCP 端点、Solver 约定、模型通道、外部资源和截止；候选决定如何组织模型上下文。
- 模型代理保管真实凭据、绑定固定字段和外部期限，转发合法请求及原始协议流；移除工具参数/空白/重复检测和固定 tools 准入。
- 用可撤销运行租约和独立监督通道替代逐请求控制数据库查询；公布撤销传播上限与监督失效处理，原截止不延长，控制服务心跳中断不新增提前停止；保留异步持久化与重启对账。
- 实现连接关闭、取消、背压和日志边界；禁止代理内部隐藏的生成重试。传输不支持时明确失败，不暗换路径或模型。
- 新链路不再创建固定 SDK Runner、逐行 JSON-RPC 命令桥及强制工具包装。原生文件、PTY、jobs 和任务端点直接在 main 内使用。
- 用独立进程身份监督退出，撤销模型通道并收回所有候选子进程；遵守 Harbor 的侧车产物收集和 verifier 生命周期。

**退出条件**：候选入口 → 假模型 → 任务工具/文件 → Harbor verifier → 新收集器 → Meta 查询全部连通；停止后无候选后台进程继续调用模型或写评分输入。

### P4 默认 Harness 组件迁移与自由替换

**产物**：可维护的默认 DSH 候选模板、独立策略插件及策略替换样例。

工作：

- 从固定启动树提取默认 profile 和启动入口，明确依赖；移除候选对平台私有 SDK/RPC 状态的依赖。
- 将输出保护、传输恢复、内容重试和完整工具参数反馈迁入候选；初始默认值可复用现有恢复增量，但允许候选改动、删去或替换。
- 工具参数校验应在实际执行前发生；坏参数不执行，完整错误通过正常工具结果反馈。是否重试和如何停止由候选决定。
- 允许动态 tools 子集、显式替换 bash/MCP 包装、不同结果展示、持久终端、异步 jobs、多会话与同 Solver 子调用。
- 保留原始工具返回、已完成副作用和有效上下文；示例恢复不得重放先前已完成工具。平台不尝试按候选算法解释“恢复链已结束”。
- H0 是普通完整候选，后续候选可从 H0 复制、组合或替换；不是不可变的隐含模板加附属插件。

**退出条件**：在平台代码和外部实验条件完全不变时，至少五种独立候选变化通过同一 freeze/test 接口：恢复策略、动态工具、上下文/压缩、多会话、依赖/profile。不得通过修改平台白名单让测试通过。

### P5 Meta 反馈、比较与独立导出

**产物**：匹配的新工具契约和开发资料、可解释比较、工作台显示及独立执行包。

工作：

- Meta 提示词与 SDK 导航明确候选所有权，提供真实框架/profile 对应资料，不继续声称只能添加固定工具之外的插件。
- 构建、冻结、正式测试、结果收集分阶段可查；原始错误可直接读取，无需先写报告或满足研究模板。
- 比较拆分候选身份、外部实验条件、平台契约身份；候选依赖和 profile 改变不再被当成不可比较的环境漂移。
- 报告/UI 同时显示官方分数、执行异常、证据缺口与条件差异；保留 v4 主指标和所有尝试。
- 导出同一候选源码/产物/锁/入口/配置及最小模型连接与 Harbor 接入组件；无需原控制数据库、Meta 或工作台。
- 旧工具契约、候选、证据及报告继续按原版本读取，禁止按当前默认值重解释历史。

**退出条件**：Meta 能从原始错误定位到候选或外部故障，修改策略并复测；用户能看懂两个完整候选的差异；导出在原仓库和数据目录不可访问时运行。

### P6 回归、真实验证与切换

**产物**：验收矩阵、真实比较证据、独立搬迁结果和明确的新默认入口。

工作：

- 执行第 4 节的离线/隔离/Harbor 契约矩阵，修复跨层问题；不把单元测试通过当端到端完成。
- 按第 5 节进行有范围的真实试验，使用同一 Solver 和相同任务条件，全部尝试计入证据。
- 新活动默认采用新契约前，完成默认 H0、可替换候选和导出包的实际运行验证。
- 只对新活动切换；旧活动继续原链路。回退选择明确版本，不在新候选下静默执行旧实现。
- 更新正式需求、架构、SDK、操作说明、导航与模板；删除新链路未再使用的固定装配入口，兼容代码有明确版本边界。

**退出条件**：验收矩阵无未解决的必需项，真实执行与官方评分可核查，独立导出经过验证；结论只声明已验证范围，不保证某个模型从此不再生成异常或科学成绩必然提高。

## 4. 验收矩阵

测试优先使用合成 provider、合成插件和可重复故障，不提交真实任务答案或私人轨迹。已有测试可迁移和扩展，新的目录/文件名由实现决定。

| 编号 | 场景与验证方法 | 必须观察到的结果 | 限制对应 |
|---|---|---|---|
| A01 | Meta 生成完整候选，构建、freeze、提交合成 Harbor 任务、查询结果 | 同一候选摘要贯穿全部阶段，得到官方产物；平台代码无需修改 | R06–R08、R33 |
| A02 | 候选增加未预装的 Node/Python 依赖及安装脚本 | 隔离构建成功；失败日志完整可读；宿主和运行凭据不可见 | R09–R10 |
| A03 | 修改 profile/框架引用或候选依赖，保持外部条件不变 | 形成新候选，可被同一比较流程接纳；实际运行内容可核对 | R07–R08 |
| A04 | 模型请求依次使用工具子集、无工具、聚合工具和新会话，候选能力说明超出旧枚举 | 不因能力标签、静态工具清单或 session 形态被拒绝 | R11–R15 |
| A05 | 替换 bash 名称/实现，使用原生文件、持久 PTY、后台 jobs | 文件与进程位于任务工作区；模型确实使用新工具；停止后工作被收回 | R12、R14–R16 |
| A06 | 假 provider 返回 503、断流、坏 JSON、空白膨胀；分别装配恢复/无恢复候选 | 策略决定重试和错误反馈，结果不同且证据清楚；代理只记录请求事实 | R18–R21 |
| A07 | 默认恢复插件中，工具已有副作用后模型失败，完整错误调用与合法调用混合 | 恢复不重复已完成操作；非法参数不执行；部分流不伪装成完成调用。此为默认插件质量要求，不增加平台策略禁令 | R18–R20 |
| A08 | 多调用策略和无工具启动策略执行 check | 不被“只能一次请求/必须有工具”误拒；检查能力和正式评分区分 | R24 |
| A09 | 并发调用、长响应、大型合法工具参数、缓慢读者 | 背压或明确容量错误，不存在未声明的 16 调用/32 MB 杀进程语义；内存有界 | R05、R18、R22 |
| A10 | 候选主动压缩、内部重试、辅助会话均使用模型通道 | 同一固定 Solver 约束生效，无用途专属授权，无重复计时 | R01、R04、R21 |
| A11 | 提交正确产物后候选非零退出；单步 Harbor 原生对照 | 保留 Agent 异常并得到官方评分；collector 不清空分数 | R28–R30 |
| A12 | Agent 超时但有产物；另测用户取消和真实环境故障 | 各自遵循原生生命周期；不为了评分延长求解或伪造成功 | R04、R28–R29 |
| A13 | 官方评分存在，候选轨迹损坏/诊断附件缺失/清理失败 | 可信官方分数保留；证据/执行问题单列 | R30–R31、R34 |
| A14 | 官方结果被篡改、归属错误或分数文件冲突 | 保存原件但不标可信成绩；不能由候选自报覆盖 | R03、R31 |
| A15 | 结果收集器第一次失败，重复执行收集 | 不重跑模型/任务，不新增 Trial；产生有来源的新投影 | R31–R34 |
| A16 | 候选尝试换模型、访问宿主/其他 Trial、读取 verifier 私有输入 | 外部边界真实拒绝；候选不能通过改工具名绕过 | R01–R03、R23 |
| A17 | 非合作进程不响应终止并保持多个后台任务 | 外部撤销通道、收回进程，其他 Trial 和评分阶段不受误杀 | R04–R05、R14 |
| A18 | 构建或队列等待很久后启动任务 | benchmark Solver 阶段仍完整计时；不足以容纳则未启动，不悄悄缩短 | R04 |
| A19 | 候选与外部条件分别变化，历史字段缺失 | 正确区分研究变量、环境差异和未知；不把新旧链路成绩直接拼成对照 | R08、R33 |
| A20 | 所有失败、未评分、人工取消和已评分样本进入报告 | 既有 v4 分母保持；官方 null 不伪造为官方 0；不挑成功子集 | R32、R34 |
| A21 | 导出后隐藏原仓库、控制数据库、对象目录与 Meta 服务 | 使用导出入口和声明配置完成装配及评分；候选摘要相同 | R35 |
| A22 | v1/v2 包和既有恢复版本执行/导出/读取 | 行为和身份保持原绑定，无热升级或默认值污染 | R33–R35 |
| A23 | 候选源码包含任务名称用于合法解析或说明 | 不因简单字符串匹配被拒绝；明确不代表通过泛化检验 | R25 |
| A24 | 已支持五任务的资源/网络/sidecar/产物规则逐项校验 | 保持已验证能力，未支持环境给出具体缺失能力；无虚假通用支持声明 | R23、R36 |
| A25 | 同一批次提交/操作重试、后台重启后对账 | 不重复构建发布或启动 Trial；已有运行仍由持久监督追踪 | R32–R33 |
| A26 | 真正磁盘满、构建容量不足、模型代理故障 | 具体阶段与平台根因可读；原始已保存结果不因后续记录失败丢失 | R05、R22、R31 |
| A27 | 控制数据库忙、控制服务短暂断开、监督失效、任务到期与主动撤销 | 独立监督存活时不因查库/心跳停顿；监督失效可收回运行，原截止和已确认撤销会停止；重启对账不重复启动 | R02、R04、R37 |

## 5. 真实验证方案

### 5.1 最小范围

实施后的第一批真实对照建议为 **2 个任务 × 2 个候选 × 2 次独立重复，共 8 个 Trial**：

- 任务选择 `time_budgeted_hamlearn_10q` 与 `time_budgeted_shadow_surrogate_60q`，覆盖不同任务时限、文件工具和较长执行流程；准确时限从已锁定 task 配置读取。
- 两个候选均运行于新链路：默认 H0 与包含明确恢复/工具变化的候选。平台监督、Solver、调用约定、任务/镜像、资源和网络条件相同。
- 对照交错安排，固定并发条件，保留所有尝试。不得拿旧双容器 H0 成绩直接证明新候选收益。
- 真实测试中观察模型请求、工具执行、候选终态和官方评分；自然运行未出现故障不算恢复路径已验证，故障注入由独立的 A06–A07 覆盖。

8 次不是统计显著性保证，也不是原活动“五任务稳定通过”目标的替代。它验证平台闭环与行为差异；扩大效果实验由后续授权和研究目标决定。其余已支持任务先做 A24 的环境和接入回归，再按需要增加真实试验。

### 5.2 资源与执行时机

执行真实验收前先核对已有授权的模型、任务、并发及总时间是否覆盖这 8 次和搬迁验证；已覆盖就直接执行，缺少的信息一次补齐，不按阶段重复申请。启动、Solver、verifier 与清理分别计时，活动剩余时间不能导致 benchmark 求解阶段被缩短。

独立搬迁真实验证至少 1 次，另计实际尝试；可以与上述对照中的一项事先统一安排，但必须明确其执行入口和条件，不能事后将不匹配的运行抵扣。构建或离线契约检查不冒充正式 Trial，也不隐式调用真实模型。

### 5.3 通过与不通过的判断

平台验收关注候选策略能够实际替换、全链路可用、官方结果完整、故障归因准确和外部边界有效。科学 0 分可以是有效实验结果，不自动判为平台验收失败；环境未启动、评分被自加门槛跳过、分数被收集器抹掉或实际运行不是所选候选，均为平台未通过。

策略收益另作结论。若两候选都完成但分数没有提高，应如实报告；不得修改成功标准或从失败集合里挑选样本使策略显得有效。

### 9.4 运行边界与交付使用

新源码默认只作用于新活动。旧活动的冻结适配器、工具与候选按原绑定运行；程序更新须保持版本兼容和在途工作完整性。

监督的轮询间隔是 0.5 秒，接收停止后先发 SIGTERM，10 秒后对 Harbor 进程组 SIGKILL；控制端超过 15 秒仍未退出则再次回收。容器引擎不可用时不能保证资源在这些时间内实际删除，所以状态必须保留未确认，不能只因发出信号声称清理完成。模型通道的本地原截止独立有效，数据库停顿不续期。

完整工程 check 是构建/完整性检查，不能泛化为所有任务的启动承诺；脚本、PTY、恢复、网络与正式评分由上述实际运行覆盖。当前模型通道支持 HTTP/SSE；WebSocket 和其他任务环境须给出明确能力缺失，不静默改协议。参考模型保持完整候选，参考 Harness 的现有 CLI 预设仍明确使用原兼容契约，不与主 Solver 混算。
