# 插件库与 H0 选择

适用：新活动的 `user-h0-v1`。从工作台导航进入「插件库」，不必先选择活动。旧活动的冻结起点保持原样。

## 保存与阅读

新工程检查或冻结时，后台先保存 `harness.json.plugins` 声明的插件源码，再进行构建。构建失败、未采用和后续被替换的版本都保留。库中以内容摘要区分版本；同名、同版本号但源码不同会是不同条目，重复内容合并来源，活动配置不改变插件内容身份。

点击「补录历史冻结插件」导入可验证的历史 v1/v2/v3 资产；页面显示持久进度、逐项异常和结果。失败后可重新补录，已保存内容不会重复。补录不会修改旧活动、编号、成绩或原冻结源码。未声明位置、缺失、损坏及不兼容资产不会被猜测修复；需要适配的源码仍可阅读。源码发布中断后后台恢复已经落盘的登记；无法恢复的条目会提示重新补录。

搜索名称、用途或来源，打开版本后可查看源码、配置规范、准确依赖、来源与构建记录。「已保存」「所在组合曾构建通过」「所在组合尝试运行」分开显示。运行成绩属于当时组合及条件，不证明其中每个插件都有效；来源活动已删除时如实提示，库源码独立保留。

## 组合本次起点

新建活动第三步为「组合 H0」。

1. 选择推荐预设（显式包含请求与响应恢复）或最小模板（无可选插件）。
2. 从列表打开插件，点击「加入 H0」，核对准确摘要并编辑 JSON 配置。依赖版本须自行逐项加入；平台不会自动选入未确认内容。
3. 点击「核对组合与配置」。类型错误、缺依赖、冲突或已删除版本会明确报错；变更后需重新核对。
4. 设置额度并创建。后台保存准确选择，在隔离环境构建并检查实际加载；此阶段不调用模型、不计时、不消耗 Trial。所有准备完成后再单独启动活动。

可选插件一键装配目前支持显式声明 `dsh-plugin-v1` 的 DSH 基础模板插件，声明不等于实际检查通过。其他框架源码标为需要适配；[SDK 插件设计](../../knowledge/plugin-sdk/guides/plugin-design.md#让用户在后续活动中组合插件)说明如何派生可组合版本。组合器不自动改写历史源码。

恢复插件使用与其他插件相同的配置和加载方式。移除它会移除该请求/响应恢复链，框架自身参数校验与工具错误反馈仍存在；平台截止、取消、后台重启和结果归集不受此开关控制。默认恢复预设被删除后不会自动复活，可使用最小模板，或到库中明确重新导入。

H0 是本活动起点的角色，组合摘要是跨活动内容身份；同样内容复用不会产生新实现。概览展示基础模板、组合摘要、选定插件和来源活动/版本。本活动没有启动对应实验时显示「本活动尚未验证」；历史成绩不并入当前统计。Meta 自行决定是否验证 H0 及验证次数；实验次数上限可以少于任务数。

Meta 只能得到本活动选定插件、已确认依赖和本活动新成果，可以继续修改、移除、派生和组合工程。它看不到全库，也不能替用户重选 H0；选择源码不自动授权来源活动的报告或轨迹。

## 删除和重新导入

版本详情可删除此版本或同名插件的全部版本。确认前展示准确范围、活动引用、库依赖、冻结候选数量和空间说明。

删除先从可选库中移除；已有活动仍可读取、运行和导出自己的冻结资产。删除来源活动不删除仍入库的源码。无引用的已删源码在存储宽限期后才可释放；删除记录保留，普通重扫和重启不会恢复可选状态。空间当前显示「待核算」，不承诺立即释放。

勾选「包含已删除版本」，打开条目并「核对重新导入」可明确恢复。若源码已经释放，先补录仍存在的历史快照；平台恢复插件仍有匹配原源码时可直接重新导入。原准确内容已经不可获得时，不能用新版内容冒充恢复。

写操作出现未知结果时，点击「用原请求核对未确认操作」；刷新后仍使用相同请求身份。创建活动也保留原选择和创建键，不能因库更新、删除或网络超时重新解析成另一个 H0。
