# 阅读研究、证据与报告

适用：Studio 当前页面。全部统计来自后台，当前规则见[计分说明](../architecture/evidence-storage.md#官方评分与任务完成分)。

## 从结论进入依据

- 「进化概览」先看方向、关键变化、当前选择及任务覆盖。
- 「插件与动机」看用途、机制、为什么修改以及相关研究；再展开冻结源码和准确内容身份。尚未形成插件的尝试也保留。
- 「版本对比」比较任务成功率、分母、条件差异与未测范围。不要只比较最高单次分数。
- 「实验记录」保留每次尝试、状态、故障层、官方结果、耗时和证据入口。
- 「研究报告」区分系统事实与 Meta 分析；「运行详情」查看会话、通知、计划、参考实验和后台工作。

插件说明表达设计意图，触发记录表达实际行为，对照与重复实验支持效果判断。同名插件不保证源码相同；机制描述不等于因果证据。缺少动机或机制时页面标明待补充，不自动生成解释。

## 理解结果

官方评分缺失仍显示未评分；当前 task-completion-v4 对已启动且最终结束的多数无评分尝试派生失败 0。未启动、无先行失败的明确人工撤销、正在运行或结束待核实单列。官方 0 是有效评分，归档失败不能覆盖已核验分数。

逐任务成功率保留全部纳入尝试，跨任务等权。没有纳入尝试的任务显示未测/待定，不凭空显示 0%。官方均分、有效评分比例与任务成功率是不同指标。

比较要核对固定模型、任务来源、镜像、平台适配、资源和时间。元数据缺失与已知条件差异分别显示；参考实验独立分组，不直接进入主线成绩。版本被保留是 Meta 的取舍，不代表平台认证效果或泛化。

## 报告、选择与历史来源

报告分批次与总报告，保留事实快照、分析正文和修订。阅读时检查实际行为、预期行为、反证、局限及下一步依据。系统后续补充事实可以形成新修订，不能覆盖旧解释；页面加载不调用模型编写报告。

版本选择保存当时明确考虑的备选、选择理由、证据摘要和重新考虑条件。未选版本不自动等于已否定；后续新结果不改旧选择快照。新活动报告不包含累计 token/费用统计。

跨活动材料通过「显式纳入历史来源」选择具体证据或报告修订、用途和访问范围。默认仅用户阅读，明确授权后才进入 Meta/研究角色材料。来源任务须在允许范围内，未纳入的跨活动 ID 仍拒绝；历史成绩不并入本活动统计。补充历史解释保留作者、事实时间与整理时间。

## 完整证据与索引进度

结果可用与证据索引完成是两个状态。后台工作显示 pending/running/complete/failed 及进度；归档尚未完成时不能把当前列表当成全部证据。工作台分页查看证据，Meta 的 evidence_list 等操作提供不可变文件入口。

摘要和短回执只用于导航。Meta 可从 `/evidence`、`/materials`、`/outputs` 等只读路径继续读取；query-tree-v1 快照按返回格式逐节点展开。每次读取校验摘要，证据片段记录准确范围。分段日志须读取 segments 清单、关闭段和尾段；直接 grep 原文件只读到尾段。

原始模型文本、工具结果和报告是来源材料，不是浏览器脚本，也不授予跨活动权限。遇到缺失/摘要错误保留诊断，不能通过手工改哈希把损坏内容伪装成完整证据。

## 收尾理由与实验总结

新活动的概览显示主 Meta 提交的结束理由和本次实验总结。后台完成在途工作后保存系统最终事实，报告中单独列出 Meta 原文。系统事实摘要和 Meta 总结保持各自来源，缺失总结会明确标记。

收尾总结不依赖每轮或最终分析报告是否齐全，也不表示平台已经认证目标达成；具体流程见[活动操作](campaigns.md#版本选择与探索结束)。历史报告保持各自快照，不补写后来的收尾决定。
